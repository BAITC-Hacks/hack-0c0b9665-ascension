# Передача приоритетов в браузерный Worker

Интеграция использует ядро и панель из `feat/h12-priority-constraints` (авторский commit `c57a41efd240b071e3320890117344845b39adac`) без изменения их логики. Контракт ограничений описан в `policy-priority-constraints.md`.

Адаптер `public/policy-options-client.js` принимает прежнее тело `{decisions}` или оболочку `{scenario, constraints}`. Оболочка `{scenario}` также допустима. При наличии собственного поля `scenario` или `constraints` тело считается оболочкой: `scenario` обязателен, другие верхнеуровневые поля запрещены (`INVALID_REQUEST`, Worker не запускается). Это исключает неоднозначное смешение старого и нового формата.

Ограничения передаются без очистки, подстановки или отбрасывания полей. В частности, `null`, неверные типы и неизвестные поля доходят до валидации официального ядра и возвращают `valid:false`, `INVALID_CONSTRAINTS`, пустые варианты и статус адаптера 422. Отсутствующее поле и пустой объект сохраняют прежнее поведение. Ошибки формы сценария также проверяет ядро.

Сообщение Worker: `{requestId, scenario, limit:6, constraints?}`. Вход Worker передаётся в `buildPolicyOptions(scenario, {limit, constraints})`. Ответ содержит исходный результат ядра; адаптер не пересчитывает показатели. `/api/policy-options` остаётся локальным логическим адресом адаптера, нового HTTP-маршрута нет.

Каждый запрос получает отдельный Worker и идентификатор. Ответ с чужим идентификатором игнорируется; отмена завершает Worker и удаляет обработчики. Панель отвечает за отмену запроса и сброс отображения при смене приоритетов или сценария. Транспорт сохраняет существующие коды ошибок и ограничения времени ожидания.

Проверка: `node --test tests/policy-constraints-transport.test.js tests/policy-options-client.test.js tests/policy-worker-bundle.test.js` и `npm run check:policy-worker`. Новые проверки исполняют опубликованный файл сборки в отдельных Node-потоках с браузерным интерфейсом сообщений через настоящий адаптер. Они покрывают совместимость, закрепление меры, районную и общегородскую защиту показателя, все закреплённые меры, ошибки, чужие ответы и отмену. Это доказательство интерфейса и содержимого сборки, не проверка браузерного UI или CPU Cloudflare.

Сборка создаётся существующим `npm run build:policy-worker`; вместе с ней обновляется `docs/evidence/policy-worker-build.json`, включая хеш авторского ядра. Зависимости и параметры сборщика не изменяются.
