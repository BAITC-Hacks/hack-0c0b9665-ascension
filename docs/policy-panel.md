# Панель альтернатив

Самостоятельный ES module `public/policy-options-panel.js` и стили `public/policy-options-panel.css`. Импорт ничего не монтирует и не обращается к DOM или сети. Панель не вычисляет Score и не реализует правила модели: отображает результаты официального симулятора, полученные через адаптер.

## Подключение интегратором

```html
<link rel="stylesheet" href="/policy-options-panel.css">
<section id="policy-options-panel"></section>
```

```js
import { mountPolicyOptionsPanel } from './policy-options-panel.js';

const panel = mountPolicyOptionsPanel(
  document.getElementById('policy-options-panel'),
  {
    dataset,                  // результат существующего /api/dataset
    city: currentCity,         // объект с hasScenarioData: true для города модели
    fetcher: policyFetcher,    // адаптер Web Worker, возвращающий Response-like объект
    timeoutMs: 12000,
  },
);

// При удалении экрана:
panel.destroy();
```

Точка монтирования должна существовать, и её `ownerDocument.defaultView` должен быть окном страницы. Один вызов монтирования на контейнер. Возвращается `{ destroy() }`; повторный `destroy()` безопасен. Стили имеют префикс `.policy-options-`.

В основной интеграции `policyFetcher` запускает предварительный расчёт в Web Worker на устройстве. Он получает логический адрес `/api/policy-options` и объект `{ method: 'POST', headers, body: JSON.stringify({ decisions }), signal }`. Передавать этот запрос в облачный HTTP endpoint не требуется. Адаптер возвращает `{ ok, status, json: async () => payload }`. Опция `endpoint` позволяет изменить логический адрес. По умолчанию `fetcher` равен стандартному `fetch`, поэтому для локального Worker нужно явно передать адаптер.

Передавайте `dataset` вместе с адаптером: тогда панель не запрашивает каталог. При отсутствии каталога панель после получения альтернатив попробует один `GET /api/dataset` через тот же `fetcher`; при ошибке отобразит коды мер и пояснение, что названия недоступны.

## События окна

| Событие | Данные и поведение |
|---|---|
| `scenario:calculated` | `{ scenario: { decisions }, result }`. Принимается только полный валидный расчёт пяти решений. Копируется снимок, старые альтернативы очищаются; поиск включается, но не запускается. |
| `scenario:invalidated` | Данные не нужны. Очищает результат и отменяет текущий запрос при изменении решений. |
| `city:changed` | `{ id, name, center, kind, hasScenarioData }`. Очищает результат. Только `hasScenarioData === true` позволяет принять следующий расчёт. |
| `scenario:load` | Панель отправляет `{ scenario }` при выборе варианта. Также слушает это событие от других панелей и очищает свой результат. |

Владелец `public/app.js` должен отправлять `scenario:invalidated` внутри существующего `invalidateResult()` после изменения выбора. Владелец города передаёт актуальный `city` при позднем монтировании либо отправляет `city:changed` после монтирования. Без явного подтверждения `hasScenarioData` поиск выключен. Панель не хранит варианты между перезагрузками и не переносит их в другой город.

После выбора альтернативы основной интерфейс получает только решения, заново проверяет их сервером и загружает в форму. Пользователь нажимает «Рассчитать» для нового основного результата. Предварительный локальный Score не заменяет основной серверный результат автоматически. Панель явно сообщает об этой границе проверки.

## Данные и состояния

Ожидается ответ `scope: 'single-decision-neighborhood'` с `valid`, `baseline`, `explored`, `validCandidates`, `paretoCandidates`, `limit`, `truncated`, `exhaustiveWithinScope`, `options`, `errors`, `emptyReason`. Вариант содержит `{ id, scenario, result, delta, changed, objectives, selectedFor }`; точные поля согласованы с модулем поиска альтернатив.

Показываются рассчитанный план, Score, оценка и название слабейшего района, стоимость, число критических показателей и дельты к текущему плану. Названия мер и районов берутся из каталога. Замена содержит удаляемую и добавляемую меру с районом. Область поиска, ограничение числа карточек и смысл вариантов Парето обозначены явно. `selectedFor` помечает приоритет варианта, а не гарантирует улучшение всех показателей. Математические правила и Pareto-фильтрация принадлежат симулятору; панель их не дублирует.

Поиск запускается только кнопкой. Обрабатываются загрузка, пустой результат, некорректный ответ, 404, 503, 422, прочие HTTP статусы, ошибка транспорта и таймаут. `AbortController` отменяет работу; номер запроса дополнительно защищает от адаптера, который игнорирует отмену. На таймауте кнопка восстанавливается даже при таком адаптере. Все динамические строки создаются через `textContent`.

## Проверки

```sh
node --test tests/policy-panel.test.js
```

20 проверок прошли: явный запрос, полнота события, копирование снимков, загрузка выбора, строгий city guard, отсутствие позднего ответа после каждого события сброса, защита нового результата от старого запроса, ошибки 404/503/422/500, ошибка сети, таймаут, пустой результат, проверка соответствия baseline, повреждённые метрики, текстовое отображение HTML-подобного имени и очистка при `destroy()`.

Изолированный browser preview на `127.0.0.1:3004` проверен с временными ответами-заглушками, числа которых получены через `simulate()`. Подтверждены отображение карточек, имён, дельт и сброс после выбора. При ширине viewport 390 px карточки идут одной колонкой, горизонтального переполнения нет; кнопки высотой 42 px. Это проверка UI, а не подтверждение работы Worker, полноты поиска или общей страницы.

Файлы общего интерфейса, сервера, Worker и симулятора эта поставка не меняет. Сквозная проверка реального адаптера и основной серверной перепроверки остаётся за интеграцией.
