# Девять разделов рабочего пространства

Все изменения расширяют существующие серверные сценарии. Расчёт и проверка плана остаются в `src/core/simulator.js`; авторизация, обращения, поручения и публикации — в существующих API кабинетов.

## Что доступно пользователю

- **Обращения жителей:** журнал, быстрые статусы и фильтры в URL, выгрузка всей отфильтрованной выборки CSV (включая страницы за пределами текущей), ссылка на карточку и переход в кабинет акима.
- **Кабинет акима:** сортировка и экспорт очередей, ссылки на обращения/поручения, сохранение существующего цикла назначения, отчёта и проверки. Закрытие изменённой формы предупреждает о несохранённых данных.
- **Демонстрация за 90 секунд:** управляемый таймер с паузой, возврат к пройденным шагам, два рассчитанных варианта, учебное поручение, проверка обратной связи, итог и перезапуск. Демонстрация не создаёт настоящих обращений.
- **Моё обращение:** ввод персональной ссылки или кода, восстановление после неверной ссылки, текущий статус и следующий шаг, существующая обратная связь/фото, выход из просмотра. Токен передаётся заголовком API и не сохраняется в browser storage.
- **Что изменилось в городе:** поиск, район, источник и подтверждение жителем, сортировка, сводные количества и подробности, фильтры в URL. Неизвестный район сбрасывается с уведомлением. При ошибке обновления потенциально снятые с публикации данные скрываются до успешного запроса.
- **Конструктор решений:** поиск по названию/коду/показателю, сортировка по стоимости/лагу, фильтр по оставшемуся бюджету, отмена до 20 изменений, автосохранение черновика, именованные варианты и восстановление после перезагрузки. Каждое изменение проходит серверную проверку.
- **Показатели районов:** выбор района, исходные данные и расчёт, критические значения, поиск/направление/сортировка показателей, CSV текущей выборки, слабые показатели и переход к подходящим мерам с выбранным районом.
- **Результат сценария:** точные JSON/CSV, ссылка с решениями для нового серверного расчёта, печатный отчёт, сравнение A/B и существующее объяснение. Изменение плана сбрасывает результат, действия экспорта и возможность сохранить устаревший снимок на сервере.
- **Как это работает:** разбор всех частей Score, вклад населения и весов каждого показателя, выбор меры и её фактический эффект с учётом лага, синергии и ответы на вопросы с переходами к соответствующим разделам.

## Контракты интеграции

`app.js` импортирует модули `district-explorer`, `method-guide`, `workspace-nav`, `workspace-tools`. Событие `simulator:ready` несёт `{ dataset, baseline }`; `scenario:calculated` — `{ scenario, result, dataset, baseline }`; `scenario:invalidated` сбрасывает рассчитанные представления; `scenario:changed` несёт `{ scenario }` для черновика. Все события отправляются после основного рендера.

Модули районов и методики отправляют `constructor:focus` с `{ measureId, districtId? }`. Это открывает меру и подставляет район, но добавление пользователь подтверждает кнопкой «Добавить в план».

`scenario-library.js` взят без изменений из `origin/main` (`56c5150`) для совместимости с уже существующей библиотекой: `akim-scenario-library-v1`, `official-astana-v1`, до 20 записей, одинаковый `createLibraryRepository`. Новый UI использует этот же репозиторий и перечитывает его перед записью; независимой второй библиотеки нет. Незаконченные варианты используют совместимый тип `imported` без снимка результата. При слиянии интерфейсов достаточно оставить один UI списка. Черновик — отдельное одиночное состояние `ascension.workspace.draft.v1`, без вычисленного результата. Содержимое черновика и ссылки повторно валидируется сервером; числа из browser storage не подставляются в расчёт.

## Проверки

- `npm test`: 93 теста, включая 6 новых проверок фильтров районов, CSV, рекомендаций, частей Score и лагов.
- `tests/workspace-navigation.e2e.mjs`: все девять ссылок, фильтры каталога, отмена, восстановление, совместимая библиотека, точный расчёт, JSON/CSV/ссылка/печать, переходы из районов и методики, ошибка сети, сброс устаревшего результата, повреждённый черновик, мобильная ширина 390 px.
- `tests/staff-navigation.e2e.mjs`: экспорт всей выборки, фильтры/ссылки, сортировка, сохранение введённых данных при отмене закрытия, мобильные очереди.
- `tests/citizen-navigation.e2e.mjs`: ввод и отзыв жителя, поиск/фильтры/повтор загрузки публикаций, таймер и этапы демонстрации.
- Существующие `tests/akim-ui.e2e.mjs`, `scripts/desk-browser-check.mjs`, `scripts/citizen-browser-check.mjs` также проходят.

Браузерным проверкам нужны Playwright и Chrome; путь пакета задаётся через `PLAYWRIGHT_PATH`. Тесты создают временные базы SQLite и отдельные browser profiles, не меняя пользовательские обращения.

Проверена локальная версия приложения. Порядок общей интеграции и публикации: `docs/deployment-coordination.md`. Эта доработка не добавляет Cloudflare-адаптер и не объединяет JSON-реестр Telegram с SQLite кабинетов.
