# Библиотека сценариев Астаны

Библиотека сохраняет именованные сценарии между перезагрузками на одном адресе сайта в одном браузере. Пользователь может вернуться к решениям, удалить запись с подтверждением или импортировать A/B из JSON сравнения для нового расчёта. Модель синтетическая; сохранённые оценки обозначены как снимки. Они не используются для нового расчёта и не являются прогнозом для другого города.

## Подключение интегратором

Файлы модуля: `public/scenario-library.js`, `public/scenario-library.css`. Модуль не импортирует ядро, не обращается к API и не запускает AI. Он не подключается автоматически.

В `index.html` подключить CSS и добавить контейнер после панели сравнения:

```html
<link rel="stylesheet" href="/scenario-library.css">
<section id="scenario-library" class="model-only"></section>
```

В `app.js` после определения текущего города:

```js
import { mountScenarioLibrary } from './scenario-library.js';

mountScenarioLibrary(document.getElementById('scenario-library'), {
  city: currentCity,
});
```

Поле `city.hasScenarioData` должно быть `true` только для официальной модели Астаны. `dataset` не требуется. Если второй аргумент отсутствует, действия заблокированы до первого `city:changed`. Повторное монтирование в тот же контейнер не создаёт вторую панель; возвращаемая функция удаляет панель и её слушатели.

| Событие на `window` | Поведение |
| --- | --- |
| `scenario:calculated`, `detail: {scenario: {decisions}, result}` | При `result.valid === true`, пяти решениях и корректных числовых полях готовит независимую копию для явной кнопки «Сохранить расчёт». Невалидное событие не сохраняется. |
| `scenario:invalidated` | Сбрасывает кандидат и выключает сохранение до нового расчёта. Введённое имя остаётся. Интегратор отправляет это событие из `invalidateResult()` при изменении/загрузке/сбросе плана. |
| `city:changed`, `detail: {id, name, center, kind, hasScenarioData}` | Скрывает действия вне модели Астаны, показывает пояснение. При каждой смене города сбрасывает кандидат и незавершённый импорт. Автоматически город не переключает. |
| `scenario:load`, `detail: {scenario}` | Библиотека отправляет только копию решений по кнопке «Загрузить в план». Приложение валидирует её сервером, обновляет план и сбрасывает старый результат; пользователь отдельно запускает расчёт. |

Внутри `invalidateResult()` нужен hook:

```js
window.dispatchEvent(new CustomEvent('scenario:invalidated'));
```

## Данные и импорт

Ключ `localStorage`: `akim-scenario-library-v1`. Контейнер `{schemaVersion: 1, entries: [...]}` содержит до 20 записей. Запись содержит `id`, имя 1–80 символов, дату сохранения `createdAt`, `modelId: "official-astana-v1"`, источник `calculated` или `imported`, копию `scenario.decisions` и `snapshot`.

У собственного расчёта `snapshot` содержит только `score`, `totalCost`, `remainingBudget`, `criticalCount`. Остальные поля результата, тексты объяснений и произвольные данные не сохраняются. Импортированные записи имеют `snapshot: null` независимо от содержимого `result` в файле. Локальное хранилище пользователь может изменить вручную: даже восстановленный снимок не считается проверенным актуальным результатом.

Принимается согласованный экспорт Алишера:

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-09-23T10:00:00.000Z",
  "slots": {
    "A": {"scenario": {"decisions": [{"measureId": "M7", "districtId": "nura"}]}, "result": {}},
    "B": null
  }
}
```

Это пример безопасного неполного набора: для успешного расчёта сервер требует ровно пять решений. Фактический экспорт `comparison.js` на ревизии `b77274b` разрешён только при двух рассчитанных слотах и содержит полные пять решений каждого. Импорт дополнительно принимает один непустой слот, когда другой отсутствует или равен `null`.

- Лимит файла и JSON — 128 КиБ в UTF-8. Неизвестная версия, ошибочный JSON, оба пустых слота или ошибочный второй слот отклоняют весь импорт.
- Решения: от 1 до 5, уникальный `measureId`, только поля `measureId` и необязательный `districtId`. Идентификаторы — 1–40 ASCII-букв, цифр, `_` или `-`; `null`, пустые/слишком длинные строки, объекты и лишние поля запрещены. Городские меры передают `districtId` отсутствующим.
- Это проверка формы, а не повторение правил симулятора. Известность мер/районов, стоимость, направление и совместимость проверяет сервер при загрузке. Неизвестный безопасный идентификатор сам по себе не запускает никаких действий.
- Весь файл проверяется до появления предварительного просмотра. Пользователь задаёт имена A/B и подтверждает сохранение. Если два сценария не помещаются в лимит 20, не сохраняется ни один; старые записи не вытесняются.
- Имена и подписи вставляются через `textContent`. JSON не исполняется; импортированные `result` не читаются и не копируются.
- Экспорт здесь не дублируется: для переноса используется существующая панель сравнения Алишера.

## Ошибки и ограничения хранения

Запись выполняется до обновления списка в интерфейсе. При ошибке квоты старый список, текущий расчёт и введённое имя остаются. Можно освободить место или удалить ненужную запись, повторить чтение и снова сохранить. Если чтение запрещено или данные повреждены, библиотека показывает предупреждение и не перезаписывает их автоматически. Сброс повреждённой библиотеки требует отдельного подтверждения в интерфейсе и не меняет текущий план приложения.

Перед изменением библиотека повторно читает хранилище и реагирует на событие `storage` от другой вкладки. Это не транзакционная командная база: одновременная запись из разных вкладок не имеет строгой гарантии блокировки. Данные не синхронизируются между браузерами, устройствами, портами или адресами развёртывания; очистка данных браузера удаляет их. Поддерживается только модель `official-astana-v1`; миграции между версиями моделей отсутствуют.

## Фактическая проверка

База реализации: `origin/main 6fcc4cb`. Проверка собственного preview — `http://127.0.0.1:3003`, основной UI и HTTP этой базы; подключение модуля внедрено в HTML ответа локального preview без изменения общих файлов. AI в preview подменён детерминированным ответом, внешние модели не вызывались. Это проверка библиотеки; окончательное подключение карты и hooks проверяет интегратор на объединённой версии.

```sh
node --check public/scenario-library.js
node --test tests/scenario-library.test.js
```

Автоматические проверки покрывают контрольный результат `56.54307`, отделение снимка от AI-текста, небезопасные формы решений, неизвестные версии, один/два/пустые слоты, UTF-8 границу 128 КиБ, повреждение storage без перезаписи, копирование данных, ограничения имён и 20 записей, атомарность двух записей, отказ квоты и повторную запись, запрет доступа к хранилищу и обновления другой вкладки.

Результат проверки 23 сентября 2026: **16/16 тестов библиотеки PASS**, общий `npm test` — **79/79 PASS**; `node --check` и `git diff --check` без ошибок.

В браузере проверено:

1. Демо → расчёт `56.54` → имя → сохранение → перезагрузка → запись остаётся, результат приложения не восстанавливается автоматически.
2. Загрузка сохранённого набора возвращает пять решений в план через серверную валидацию без автоматического simulate/AI; отмена удаления оставляет запись, подтверждение удаляет её.
3. Импорт A/B через обработчик файлового поля с поддельными результатами сохраняет только решения и `snapshot: null`. После загрузки B с M7 в Есиле реальный сервер даёт `55.30`. Файловая фикстура внедрена через `File`/`DataTransfer`; системный диалог выбора файла отдельно не проверялся.
4. Имя `<img src=x onerror=alert(1)>` остаётся текстом; DOM-элемент изображения не появляется.
5. При тестовой `QuotaExceededError` старые записи и имя остаются; после восстановления записи и «Повторить чтение» сохранение проходит.
6. Повреждённый JSON показывает предупреждение; отмена сброса сохраняет исходное повреждённое значение и введённое имя.
7. События `city:changed` и `scenario:invalidated` блокируют сохранение вне Астаны и для устаревшего результата; без начального города панель ожидает контекст.
8. Неизвестная версия импорта отклоняется понятным сообщением. При ширине 390 px у библиотеки нет горизонтального переполнения; визуально проверены поля и кнопки. Ошибок в консоли preview не обнаружено.
