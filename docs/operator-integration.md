# Рабочий маршрут и 3D-карта

Интеграция подключает готовые модули к общему интерфейсу: фокус на районе перед картой, 3D-исследование города, записку по последнему расчёту, локальный реестр поручений с паспортами реализации и реестр источников данных. Карта использует географию OpenStreetMap; движущийся транспорт — явно обозначенная симуляция, не GPS.

`app.js` монтирует панели после загрузки датасета, с одной текущей территорией. Уход из модели Астаны очищает результат и записку. Сохранённые вручную поручения остаются доступны; переход к ним не возвращает карту в Астану. Создание нового набора поручений требует свежего расчёта. Реальные наблюдения в паспортах не меняют учебную формулу Score.

`district-focus` присутствует ровно один раз в начале приложения. Стили компонентов загружаются перед общим оформлением и анимациями; `city-explorer.css` подключён явно с меткой `data-city-explorer`, исключающей повторную загрузку из карты. При повторной инициализации освобождаются обработчики всех панелей и карта.

## Проверка в браузере

Локальный сервер `127.0.0.1:3029`, без ключа API, 23 сентября 2026:

- Все три новые панели действительно смонтированы. Смена размера и открытие 3D-карты не дали ошибок в консоли.
- Официальный сценарий A дал 56.54 в интерфейсе, стоимость 95 и остаток 5; записка отобразила пять мер, восемь кварталов, ограничения и синтетический характер данных.
- Кнопка скачивания создала автономный `decision-brief-2026-09-23.html`, 13 981 байт. В файле есть результат 56,54, предупреждение и нет внешних script-зависимостей.
- Созданы пять черновиков поручений. Тестовые ответственный и критерий сохранены вручную; после перезагрузки они сохранились. Уход в Алматы скрывает записку, сохраняет реестр доступным и блокирует создание поручений по отсутствующей модели.
- При ширине 390 px документ также имеет ширину 390 px; четыре нижних перехода имеют ширину больше 44 px. `prefers-reduced-motion: reduce` ставит транспорт на паузу. Снимок мобильной эмуляции встроенного браузера на данном Windows-масштабе оказался обрезан, поэтому визуальная оценка телефона проверяется отдельно.
- Независимое чтение diff подтвердило отсутствие повторяющихся ID, соответствие mount/dispose, наличие ресурсов и правильный порядок CSS. Общая проверка качества на этом этапе: 65 JS-файлов, 91 локальный импорт, пять общих защитных заголовков.
