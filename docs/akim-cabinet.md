# Кабинет акима

Адрес: `/akim.html`. Работает на том же сервере и в той же SQLite-базе, что и кабинет обращений `/desk.html`. Вход общий. Новый кабинет не изменяет официальный датасет и формулу симулятора.

## Первый запуск

1. Создать учётную запись руководителя: `npm run desk:user -- akim akim`.
2. Создать исполнителя: `npm run desk:user -- executor operator`.
3. Скрипт покажет сгенерированный пароль один раз. Для заранее выбранного пароля используется `DESK_NEW_PASSWORD`; не записывайте его в репозиторий.
4. Запустить `npm start`, открыть `/akim.html` и войти. В пустой базе создать тестовые обращения через `/desk.html`.

Создание пользователя с уже существующим логином меняет его пароль/роль и завершает прежние сессии. Все обращения, поручения, группы, сценарии и персональные настройки сохраняются после перезапуска. Автоматического наполнения базы вымышленными обращениями нет.

## Что делает аким

- **Сводка.** Получает поступившие сегодня обращения, открытые обращения высокого приоритета, просроченные поручения, отчёты на проверке и личный контроль. Нажатие на показатель открывает соответствующую выборку. «Сегодня» и сроки вычисляются по времени Астаны (`Asia/Almaty`); поручение со сроком сегодня ещё не просрочено.
- **Проблемы по районам.** Схема показывает пять районов учебного набора; это не географические границы и не точки реальных адресов. Обращения без района остаются в отдельной выборке. Количество жалоб не является оценкой благополучия района.
- **Группы.** Предложения похожих жалоб проверяет человек. Подтверждённая группа хранит ссылки на оригиналы; объединение и разъединение не удаляет жалобы и не меняет их статусы. Одна жалоба входит максимум в одну активную группу. Для группы нужен один район и одна категория.
- **Поручения.** Руководитель выбирает одно или несколько обращений, ответственного, срок и ожидаемый результат. Можно менять назначение и срок, брать задачу на личный контроль и запрашивать отчёт с пояснением. История фиксирует автора и время каждого изменения.
- **Проверка.** Исполнитель описывает выполненное и при необходимости прикладывает фотографии «до» и «после». Руководитель проверяет отчёт и указывает основание принятия либо возвращает работу с причиной. Статус поручения меняется отдельно от статуса жалобы.
- **Решения.** Из обращения выбираются меры того же направления. Это подбор по категории, а не подтверждение пригодности меры. Аким формирует комплект из пяти мер, проверяет совместимость и бюджет, рассчитывает, сохраняет и сравнивает сценарии. При сравнении сохранённых вариантов сервер заново рассчитывает оба по текущим правилам.
- **Совещание.** Формируется отчёт за выбранный период, доступный для печати и сохранения в HTML. Поступления и события проверки относятся к выбранному периоду; просрочки, ожидающие проверки поручения и группы показаны на момент формирования. Возвращённая позже работа не стирает историческое событие проверки.
- **Телефон и языки.** Интерфейс кабинета поддерживает русский и казахский. Язык и фильтры сохраняются для учётной записи. Текст жителей, имена пользователей и введённые сотрудниками комментарии сохраняются в исходном виде.

## Жизненный цикл и права

`assigned` (в работе) → `reported` (исполнитель отчитался) → `verified` (результат проверен). Из `reported` или `verified` руководитель может вернуть в `assigned`. Нельзя подтвердить исполнение до отчёта. Повторный отчёт после возврата сохраняется рядом с предыдущими; история проверок не удаляется.

Роли `admin` и `akim` могут создавать/изменять поручения, группировать жалобы, запрашивать отчёт и проверять результат. `operator` может отчитываться по своим поручениям. Личный контроль персонален: действие одного пользователя не снимает контроль другого. Чтение кабинета доступно авторизованным сотрудникам.

Отчёт требует текста; фото необязательно. Вложения должны принадлежать связанным обращениям, одно фото нельзя считать одновременно «до» и «после». Загрузка использует общее хранилище обращений: JPEG/PNG/WebP, до 2 МБ, до пяти фото на обращение.

Бот пока не подключён. Запрос отчёта — запись в рабочем кабинете, а не доставленное сообщение сотруднику. Проверка руководителем не выдаётся за подтверждение жителя. Если связанная страница жителя сохранила `residentFeedback`, карточка показывает его ответ «Подтверждено» или «Проблема осталась», комментарий и время отдельно от проверки сотрудника. Обмен через Telegram подключается после готовности интеграции Данияра.

## Надёжность

- Сервер проверяет сессию, роль и допустимость действия. Изменяющие запросы используют защиту `X-Desk-Request` и проверку `Origin`.
- У поручений и групп есть версия. Устаревшая запись возвращает 409 вместо молчаливого перезаписывания. Версия повторно проверяется внутри транзакции после чтения тела запроса.
- Создание поручений/групп использует `requestId`: повтор идентичной отправки не создаёт дубль; тот же ключ с другими данными возвращает конфликт.
- Даты, ответственные, существование жалоб и принадлежность фото проверяются на сервере. Неизвестные поля не применяются.
- Пользовательские тексты экранируются в интерфейсе и выгружаемом отчёте.
- Настройки хранятся отдельно для каждого логина. Исходный текст жалобы и контрольные показатели симулятора не изменяются действиями кабинета.

## Файлы и проверка

- `src/desk/akim-api.js` — API, хранение поручений/групп/настроек, сводки, отчёт.
- `public/akim.html`, `public/akim.js`, `public/akim.css` — кабинет, формы действий, отчёт и переводы.
- `public/akim-decisions.js`, `public/akim-decisions.css` — выбор мер, серверный расчёт, сохранение и сравнение.
- `tests/akim.test.js` — HTTP-приёмка поручений, прав, групп, дат, версий и настроек.
- `tests/akim-ui.e2e.mjs` — браузерная проверка с отдельной временной базой; основной набор запускается командой `npm test`.

Хранилище дополнено таблицами `akim_tasks`, `akim_groups`, `akim_preferences`. Они создаются при первом авторизованном обращении к API кабинета. Используется прежняя резервная копия SQLite; отдельной копии файлов для кабинета не требуется.
