# Локальный реестр действий

Модуль переводит выбранные пять мер в **ручной черновик**: ответственный, срок, критерий проверки, статус и подтверждение результата. Это локальный прототип, не система официальных поручений. Учебные эффекты и Score не подтверждают выполнение и не обосновывают реальные управленческие решения. Названия органов, исполнители и сроки автоматически не назначаются.

## Подключение владельцем интерфейса

Изменения `app.js` и `index.html` остаются у интегратора. После получения `dataset`:

```html
<link rel="stylesheet" href="/action-register.css">
<section id="action-register-panel"></section>
```

```js
import { mountActionRegister } from './action-register.js';

const actionRegister = mountActionRegister(
  document.getElementById('action-register-panel'),
  { dataset, city: currentCity },
);
// currentCity: { id, name, hasScenarioData, ... } — фактически выбранный город.
// При размонтировании:
actionRegister.dispose();
```

Для отдельной панели общего реестра handle также содержит:

```js
const document = actionRegister.getDocument();
// Только после явного подтверждения замены в панели, с предложением резервной копии:
const { savedLocally } = actionRegister.applyDocument(receivedDocument);
```

`getDocument()` возвращает независимую проверенную копию `{schemaVersion:2,registers}`. `applyDocument()` сначала проверяет **весь** документ, затем пишет локальное хранилище и только после успешной записи заменяет карточки. Если хранилище недоступно, переполнено, повреждено или конфликтует с другой вкладкой, выбрасывается ошибка `code='STORAGE'`; текущие карточки и ручные поля остаются прежними. При успехе возвращается `{savedLocally:true}`, а текущий расчёт сбрасывается. Полученные снимки — справочные, они не являются подтверждёнными сервером расчётами и не включают генерацию.

Чистая функция `normalizeActionDocument(document,{maxBytes=128*1024}={})` экспортируется из того же модуля и не обращается к DOM/сети/хранилищу. Это общий строгий контракт документа: только версия 2, известные поля, до 10 наборов по 5 действий, корректные статусы/даты/числа/вложенные паспорта, до 128 КиБ в UTF-8 (можно задать меньший лимит). Неизвестные поля, циклы и не-JSON значения отклоняются. Ошибка `code='INVALID'` не меняет состояние. Вызов методов после `dispose()` даёт `code='DISPOSED'`. Миграция версии 1 доступна только при локальном чтении, не через этот транспортный контракт.

Подключение `mountTeamWorkspace`, подтверждение Pull, резервная копия и серверная ревизия принадлежат панели общего реестра; эти методы сами не синхронизируют данные. Обычный локальный реестр может быть больше транспортных 128 КиБ: в таком случае общий экспорт через `getDocument()` отклоняется, а существующая кнопка локального JSON-экспорта остаётся доступна. Проверка другой вкладки — последовательный best effort, не обещание атомарной межвкладочной транзакции.

Проверка методов обмена: 8 новых тестов, всего **40/40** по трём файлам `tests/action-register*.test.js`. Проверены независимые копии, строгие вложенные поля и типы JSON, геттеры без исполнения, нестандартные свойства массивов, точная граница UTF-8, полная валидация до изменения состояния, успешная замена/сброс актуальности и отсутствие потери прежнего DOM/данных при отказах хранилища. Браузерную приёмку неизменённых карточек не повторяли; реальный Pull/Push проверяет владелец общей панели после подключения.

Не помещать контейнер внутрь скрываемого `.model-only`: при выборе другой территории генерация отключается, но прежний ручной реестр должен оставаться доступен. Подключить до первого расчёта. Поздний mount принимает текущий город, но намеренно требует нового успешного расчёта: сохранённые цифры не делают сценарий актуальным.

| Событие `window` | Поведение |
| --- | --- |
| `scenario:calculated`, `detail={scenario:{decisions},result}` | Только `result.valid===true`, пять уникальных известных мер с корректными районами и числовой сводкой, при `city.hasScenarioData===true`. Создаёт независимый снимок в памяти, без поручений до явного нажатия. |
| `scenario:invalidated` или `scenario:load` | Снимает актуальность и отключает создание. Ручные записи и введённые поля сохраняются. |
| `city:changed`, `detail={id,name,...,hasScenarioData}` | Снимает актуальность даже при возврате в Астану. Для другой территории расчётные события игнорируются. |

Событие успешного серверного расчёта — доверенный контракт приложения, не криптографическое подтверждение. Модуль не пересчитывает формулу и не принимает импортированные цифры как актуальный расчёт.

## Ручной процесс

1. Рассчитать текущий сценарий и нажать **«Создать черновик поручений»**. Получится один набор из пяти закрытых карточек. Заголовки содержат меру, район, статус, исполнителя и срок; неизвестные поля помечены «нужно уточнить».
2. Раскрыть нужную карточку мышью либо клавишами Tab и Enter/Space. Ввести ответственного, срок и критерий проверки. Первоначальный статус — **Черновик**, поля пустые.
3. **В работе** требует непустого ответственного и существующей календарной даты. **Выполнено** дополнительно требует ручного непустого подтверждения результата. **Отложено** задаётся вручную. Критерий проверки остаётся ручным полем без автоматически выдуманного содержания.
4. Чтобы очистить обязательные поля начатого или выполненного поручения, сначала вручную вернуть **Черновик**. Отклонённое изменение сопровождается объяснением и сохраняет прежнее значение.
5. Дата сравнивается как `YYYY-MM-DD` с локальной календарной датой браузера, без преобразования даты срока в UTC. Срок сегодня ещё не просрочен. В число просроченных входят все невыполненные статусы, включая отложенные.

Изменение одного поля не пересоздаёт карточки и не сбрасывает фокус. Последующие расчёты добавляют отдельные наборы только по кнопке. Один и тот же набор мер/районов в одном городе не дублируется при двойном клике, повторном расчёте, перестановке решений или перезагрузке. Предел — 10 наборов / 50 поручений. Удаляется только явно выбранный набор после отдельного подтверждения; отмена ничего не меняет.

## Сохранение и перенос

Ключ `localStorage`: **`akim-action-register-v1`** (сохранён для совместимости). Текущий формат `{schemaVersion:2,registers:[...]}`. Версия 1 читается с добавлением пустых паспортов только в памяти; исходное хранилище обновляется до версии 2 при следующем ручном изменении. ID, исходный снимок, ручные поля, статусы и подтверждения сохраняются. Каждый набор хранит ID, дату создания, город, исходные решения, подписи мер/районов, дату расчёта и сводку результата: `valid`, `score`, `totalCost`, `remainingBudget`, `criticalCount`. Ручные поля хранятся отдельно. Чужие поля события, объяснения AI и ответы других модулей не копируются.

Обычные изменения сохраняются сразу. Повреждённый JSON, неизвестная версия, неверные поля или вложенная структура не перезаписываются. При недоступном хранилище/переполнении изменения остаются в памяти, а сообщение просит экспортировать JSON до закрытия страницы. Если другая вкладка изменила реестр, автоматическое сохранение останавливается, чтобы не затереть её данные. Автоматического слияния нет. Перезагрузка при несохранённых изменениях может их потерять — состояние сохранения показывается явно.

**JSON** содержит полный ручной реестр, паспорта и исходные снимки; **CSV** — строки поручений, исходный набор решений и 14 колонок паспорта (25 колонок всего). Ручные значения экранируются, потенциальные формулы CSV сохраняются как текст. Экспорт не удаляет записи. Автоматического импорта ручного реестра пока нет; это переносимый файл для чтения и последующей обработки. Библиотека сценариев и экспорт A/B не изменены.

Текст в интерфейсе: **«Локальный черновик в этом браузере. Не отправлено исполнителям. Нет синхронизации и официального согласования».** Модуль не выполняет сетевых запросов, не передаёт ручные поля серверу или AI. Очистка данных браузера удаляет локальный реестр; для сохранения вне браузера нужен экспорт.

## Паспорт реализации (версия 2)

Внутри каждой карточки находится отдельно свёрнутый **«Паспорт реализации»**. Он хранит только ручные сведения:

- Площадка / адрес; при пустом поле — «не определена». Основание выбора и необязательная ссылка на источник (HTTP/HTTPS, без автоматического открытия или запроса).
- Физический KPI: название, единица измерения, исходное и целевое значения, источник. Значения не подставляются из учебного Score.
- CAPEX и OPEX в тенге, источник сметы, период эксплуатационных затрат и дата сметы. Это не перевод 100 условных единиц в деньги. Никакие реальные цены автоматически не оцениваются.
- Инфраструктурные предпосылки и следующий шаг.

Пустые числовые поля сохраняются как `null`; введённый `0` означает явный ноль. CAPEX/OPEX неотрицательны, KPI может быть знаковым; числа конечные, по модулю не выше `Number.MAX_SAFE_INTEGER`. Неполная ссылка во время набора не обрывает ввод: она не сохраняется до корректного значения; при уходе из неверного поля возвращается сохранённое значение с объяснением.

Список **«Нужно уточнить перед реализацией»** перечисляет конкретные незаполненные поля, включая ответственного, срок и критерий проверки. Основание площадки можно описать текстом или ссылкой. Даже заполненный паспорт требует проверки источников и реализуемости человеком. Список консультативный: не блокирует сохранение черновика; «В работе» допускает работу по сбору сведений. Выполнение по-прежнему требует ручного подтверждения и не выводится из модели или заполненности паспорта.

Добавленный фрагмент каждого `action`:

```json
{
  "implementation": {
    "siteAddress": "",
    "siteBasis": "",
    "siteSourceUrl": "",
    "kpi": { "name": "", "unit": "", "baseline": null, "target": null, "source": "" },
    "budget": { "capexKzt": null, "opexKzt": null, "estimateSource": "", "estimateDate": "" },
    "prerequisites": "",
    "nextStep": ""
  }
}
```

Для будущего общего хранилища с архитектурным владельцем согласован **предлагаемый**, ещё не подключённый контракт:

```js
repository.read(); // -> { schemaVersion: 2, registers, revision }
repository.write({ schemaVersion: 2, registers }, { expectedRevision }); // -> { revision }
```

`revision` выдаёт сервер; клиент не задаёт следующую ревизию. Перед атомарной записью проверяется весь документ. Конфликт — `409 CONFLICT` с актуальной ревизией, без молчаливой перезаписи. Роли и автор аудита берутся из серверной сессии, а не из экспортированного JSON. Другие ошибки: `UNAVAILABLE`, `QUOTA`, `INVALID`. Этот контракт не реализует синхронизацию; текущий mount по-прежнему принимает только `{dataset,city}` и сохраняет только локально.

Независимое review изменения не выявило блокеров.

Ввод тестового адреса и URL по символам сохранился после reload; KPI `baseline=0`, `target=10` и `CAPEX=0` сохранились, неизвестный OPEX остался пустым.
