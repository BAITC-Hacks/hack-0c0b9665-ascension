# Паспорта данных для подготовки решения

Модуль показывает происхождение официального синтетического набора и позволяет вести отдельно реальные наблюдения. Значения не поступают в симулятор и не меняют Score. Заполненная форма не означает проверенную причинную модель эффекта.

## Подключение

```js
import { mountEvidenceRegister } from './evidence-register.js';
const dispose = mountEvidenceRegister(container, { dataset, city: currentCity });
```

Подключить `evidence-register.css`. Контейнер можно разместить рядом с методикой; основные сведения видны сразу, длинная форма раскрывается по запросу. Модуль слушает `city:changed` и браузерное `storage`. Генерация данных, API-вызовы и серверные записи отсутствуют. Для неизвестной территории форма недоступна; сохранённые записи Астаны остаются в хранилище. `dispose()` прекращает обработку позднего чтения файла и удаляет слушатели.

## Поведение

- Паспорт связывает направление модели с отдельной физической величиной и территорией (район учебного набора либо весь город). Само связывание не подтверждает соответствие действующим административным границам.
- Сохраняются величина, числовое значение, единица, период, источник, владелец, охват, метод и ручная проверка. Пустое значение хранится как `null`, нулевое сохраняется как ноль.
- Черновик может быть неполным. Для отметки «проверено пользователем» нужны все поля свидетельства, имя проверяющего и дата. Это ручное заявление, не официальная сертификация и не проверка ссылки сервером.
- Невозможные даты, обратный период, URL с паролем или протоколом кроме HTTP/HTTPS, неизвестные поля и нечисловые значения отклоняются. Будущий период или дата проверки не считаются завершённой проверкой. Период старше 365 дней помечается как требующий внимания; возраст сам по себе не делает данные ложными.
- Каталог даёт пять первичных источников БНС/акимата с конкретными ограничениями периода, охвата и совместимости. Проверка каталога 23.09.2026 не является датой измерений. Источники не копируются в официальный набор и не переводятся автоматически в 0–100.

## Хранение и перенос

Ключ `akim-evidence-register-v1`, до 60 уникальных пар показатель/территория, JSON до 128 КиБ. Сбой чтения/повреждение не перезаписывает существующее хранилище. При отказе записи интерфейс не сообщает о сохранении. Для работы нескольких вкладок учитываются события `storage`; это локальный прототип, не многопользовательская база с транзакциями.

Экспорт: `{schemaVersion:1,modelId:'official-astana-v1',exportedAt,records}`. Импорт сначала проверяет весь файл, показывает количество совпадений и требует явного нажатия для замены. Все импортированные записи получают статус черновика и требуют повторной проверки, включая ранее помеченные в другом браузере. Позднее чтение старого файла или смена города не применяет импорт. HTML строится через `textContent`; пользовательские источники открываются с `noopener noreferrer`.

## Проверка

`node --test tests/evidence-register.test.js` проверяет границы данных, календарь, доверие импорту, целостность слияния и отказ хранилища. Ручной браузерный сценарий: раскрыть форму → сохранить черновик → проверить пропущенные поля → заполнить свидетельство и ручную проверку → перезагрузить → экспортировать/импортировать с повторной проверкой → сменить город → убедиться, что данные сохранены, а форма недоступна. Проверить 390 px и клавиатуру.

Проверено 23.09.2026: 15/15 целевых тестов, включая импорт собственного экспорта из 60 паспортов у лимита размера. В изолированном браузерном стенде при 390×844 ширина документа 375 px: нулевое значение сохранено как 0, строка `<script>alert(1)</script>` отображается текстом, исполняемые узлы не созданы; неполный паспорт не получает отметку проверки; после перезагрузки черновик сохранён; другой город скрывает форму, возврат сохраняет запись; раскрытие и закрытие работают клавишей Enter, фокус виден. Отдельно проверено: предварительный импорт с нулём совпадений → ручное создание записи с тем же ключом → старое подтверждение скрыто, свежая запись не заменена. Ошибок консоли нет. Эти проверки относятся к модулю; совместная приёмка после подключения в основное приложение выполняется интегратором.

## Что требуется для реального внедрения

Ведомственные источники, актуальные территориальные коды/границы, методики и калибровка эффектов должны быть подтверждены отдельно. Количество школ не определяет обеспеченность местами; число введённых поликлиник не определяет доступность медицинской помощи. В интерфейс не следует вводить персональные данные, закрытые документы или ссылки с секретами.
