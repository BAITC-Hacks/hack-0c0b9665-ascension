# Кабинет обращений: запуск и эксплуатация

## Что готово до бота

`/desk.html`: вход команды, журнал, поиск и фильтры (включая даты UTC), пагинация, создание демо-обращений, карточка, история, назначение ответственного, категория, район, приоритет, переходы статусов, внутренние комментарии, отдельные ответы жителю, фото, переход к мере в симуляторе, сохранение сценариев на сервере и их сравнение. Все созданные здесь обращения демонстрационные. Отправки в Telegram нет; ответы явно отмечены как неотправленные и автоматически впоследствии рассылаться не будут.

SQLite включает обращения, фотографии, пользователей, сессии и сценарии. Числовые результаты при сохранении сервер пересчитывает сам. Симулятор остаётся на `/`. Дополнительный кабинет акима `/akim.html` разрабатывается параллельной задачей и использует ту же авторизацию.

## Локальный запуск

Нужен Node.js 24+. Установка зависимостей для сервера не требуется.

```sh
npm run desk:user -- admin admin
npm run desk:user -- alisher operator
npm start
```

Команда учётной записи генерирует случайный пароль и выводит его один раз. Передайте его участнику приватно. Повтор команды меняет пароль и завершает старые сессии. `DESK_NEW_PASSWORD` позволяет задать пароль через окружение, от 12 символов. Не передавайте пароль аргументом командной строки и не добавляйте его в git. Роли: admin, akim, operator; кабинет обращений доступен всем трём, полномочия кабинета акима проверяет его API.

Открыть `http://127.0.0.1:3000/desk.html`. Срок сессии — 8 часов; cookie HttpOnly и SameSite=Strict. После истечения сессии войдите повторно. Пароли хешируются scrypt. Восемь неверных попыток с одного адреса блокируют вход на 15 минут; при reverse proxy настройте также ограничения на прокси, поскольку сервер не доверяет произвольному X-Forwarded-For.

## Кнопки и ошибки

- «Создать демо-обращение» открывает форму. «Зарегистрировать» проверяет поля и сохраняет с ключом повторной отправки; при сбое форма остаётся.
- «Найти» применяет фильтры, «Сбросить» возвращает весь список, «Обновить» запрашивает данные заново. Пустая выборка не выдаётся за ошибку.
- «Назад»/«Далее» доступны только при наличии страницы. Статистика соответствует текущим фильтрам, а не всей базе.
- «Открыть» загружает актуальную карточку. «Сохранить изменения» проверяет переход статуса; для уточнения, решения и отказа нужен ответ. Высокий приоритет требует причины.
- «Обновить карточку» предупреждает о потере несохранённых изменений. Конфликт версий не затирает чужие правки: скопируйте свой текст, обновите карточку и повторите.
- «Загрузить фото» принимает JPEG/PNG/WebP до 2 МБ, до пяти фото. Просмотр требует действующей сессии. Для защиты от потери текста загрузка предупреждает об обновлении формы.
- «Открыть меру в конструкторе» передаёт выбранную меру и район, связывает будущий сохранённый сценарий с обращением. До расчёта нужно собрать пять допустимых мер.
- «Сохранить сценарий» сохраняет последний рассчитанный набор, а не ещё не рассчитанные изменения формы. При отсутствии входа откройте кабинет в другой вкладке, войдите и повторите.
- «Сравнить» выбирает две сохранённые версии; третья замещает первую. Повторное нажатие убирает выбор. «Загрузить» возвращает набор в конструктор для нового расчёта.
- «Закрыть», Escape и уход со страницы предупреждают о несохранённых изменениях. «Выйти» завершает серверную сессию.

## Проверка

```sh
npm test
```

Для браузерного сценария нужен отдельно установленный Playwright и Chrome:

```sh
PLAYWRIGHT_PATH=/absolute/path/to/playwright node scripts/desk-browser-check.mjs
```

Тест использует временную БД, проверяет вход/выход, создание, статусы, обязательный ответ, фото, обновление карточки, поиск/сброс, передачу меры, сохранение/сравнение/перезагрузку и ширину 390 px. Playwright не является зависимостью работающего сайта.

## Резервные копии и восстановление

```sh
npm run desk:backup
```

Создаёт согласованную SQLite-копию в `backups/`, включая фото, проверяет `integrity_check`. Храните копию вне сервера с ограниченным доступом. Автоматический график резервирования на хостинге нужно настроить отдельно; команда сама не создаёт расписание.

Восстановление: остановить сервер; сохранить текущий каталог `var` целиком в отдельное безопасное место; положить проверенную копию по `DESK_DB_PATH` в новый чистый каталог без прежних файлов `-wal` и `-shm`; запустить сервер; проверить вход, карточку, фото и сценарии. Для безопасности после восстановления сбросить пароли командой `desk:user`, которая отзывает сессии. Не заменять SQLite-файл под работающим процессом. Автотест проверяет восстановленную копию с обращениями и фотографией.

## Развёртывание

Подготовлены Dockerfile и compose.yaml. Это конфигурация запуска, а не доказательство опубликованного сайта.

```sh
docker compose up -d --build
docker compose exec web npm run desk:user -- admin admin
docker compose exec web npm run desk:backup
```

Данные и копии находятся в постоянных named volumes. Перед обновлением сделать копию; не применять `docker compose down -v`. За reverse proxy настроить HTTPS, передавать исходный Host, ограничить запросы, разрешить загрузки до 3 МБ и закрыть прямой публичный доступ к порту 3000. `COOKIE_SECURE=true` требует HTTPS; локально без HTTPS использовать npm start с `COOKIE_SECURE=false`.

Публичный `/api/health` проверяет HTTP; `/api/desk/health` после входа дополнительно проверяет доступность базы. Не публиковать каталог базы и копий. Контрольные тесты не подтверждают доступность конкретного домена, TLS, внешнего диска или резервирования хостинга — это проверяется после выбора площадки и развёртывания.

## Следующий этап: Данияров бот

Согласовать контракт из `telegram-complaints-plan.md`, затем добавить отдельную аутентификацию сервиса бота, приём реальных обращений, очередь исходящих событий и подтверждение доставки. Не использовать командные cookies как токен интеграции. Текущие демо-ответы не ставить автоматически в очередь реальным жителям.
