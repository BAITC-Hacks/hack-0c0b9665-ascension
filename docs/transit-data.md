# Автобусы и остановки

Под картой открывается панель «Автобусы и остановки». В Астане доступны **127 уникальных автобусных маршрутов** из 20 предоставленных пользователем скриншотов Avtobys от 23.09.2026, поиск по номеру/конечным, список остановок и их отображение на общей карте. Буквенные варианты сохранены отдельно: 4А, 15А, 24Н, 55А, 55Б, 307А и другие. Латинское `15A` находит `15А`.

У 25 записей подпись обрезана или скрыта. Они помечены; недостающие конечные не восстановлены догадкой. У №49 обе конечные отсутствуют на исходном изображении. Каждый объект `public/transit-catalog.js` сохраняет имя исходного скриншота для сверки. Сами изображения и локальные пути не публикуются. Каталог фиксирует содержание скриншотов, а не гарантирует действительность каждого маршрута сегодня.

## Реальные геоданные и границы

`public/transit-astana-stops.json` содержит **966 остановок**, OSM ID, названия там, где они есть, координаты, ссылки и исходные `route_ref`. База OSM: **22.09.2026 08:45:51 UTC**, загрузка 23.09.2026. Публичный запрос дал 968 точек в Астане и окрестностях; две за границами рабочего bbox `[50.967,71.1504,51.327,71.7104]` отфильтрованы. Снимок доступен без обращения к внешнему API; запуска приложения без интернета достаточно для каталога и текстового списка. Подложка карты требует сети и WebGL.

Источник: [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API), `https://overpass-api.de/api/interpreter`. Данные: [© OpenStreetMap contributors, ODbL 1.0](https://www.openstreetmap.org/copyright). Атрибуция отображается в панели; дата снимка и дата загрузки видны пользователю. Наличие остановки в OSM не подтверждает её эксплуатационный статус.

Геометрия автобусных маршрутов Астаны в проверенном ответе OSM отсутствует: **0 relations `route=bus`** даже в расширенном bbox `(50.5,70.5,51.7,72.0)`. Из конечных и координат остановок не создаются искусственные линии. Связь остановки с номером показывается только при явном `route_ref`; порядок этих остановок неизвестен.

**GPS, расписания, время прибытия, действующее количество автобусов и диспетчерские данные не подключены.** Движущиеся машины существующего режима «Город 3D» остаются отдельно обозначенной симуляцией. Транспортная панель не меняет Score, синтетические районные показатели или бюджет.

## Обновление и другие города

«Обновить из OpenStreetMap» делает один явный запрос вокруг центра выбранного города, ограниченный ±0,18° широты / ±0,28° долготы. Это географическая выборка, не административная граница и не полный реестр перевозчика. Для других городов Казахстана используются только их ответы OSM; каталог Астаны туда не переносится. Если OSM содержит маршруты, можно выбрать направление и загрузить его сегменты/остановки; наличие геометрии в каждом городе не гарантировано. Сегменты отдельных ways не соединяются вымышленными отрезками.

Клиент использует form POST без ключа и credentials; CORS `Access-Control-Allow-Origin: *` проверен живым запросом 23.09.2026. JSON/custom headers не требуются. Ограничения: таймаут 20 с, не чаще одного обновления города за 15 с, кэш до 10 городов на 10 минут, до 1500 остановок / 500 направлений в результате. Автоматического опроса нет. При перегрузке API ранее загруженные данные сохраняются. При смене города/направления устаревший запрос отменяется и не меняет интерфейс. Для массовой эксплуатации нужен собственный Overpass или согласованный поставщик; публичный инстанс не имеет SLA.

Поздняя проверка тем же днём: запрос через PowerShell ранее получил HTTP200 с CORS, но прямые Chrome/Node-запросы получили HTTP406 без CORS (причина не установлена). Поэтому успешное онлайн-обновление из браузера на этом окружении **не подтверждено**; реальный отказ и сохранение каталога/снимка проверены. Поставляемые данные получены успешным реальным запросом; работоспособность интерфейса не зависит от доступности обновления.

Обновить поставляемый снимок вручную:

```sh
node scripts/refresh-transit-snapshot.mjs
```

Скрипт откажется заменять файл пустым, ошибочным или усечённым ответом. Проверка точного количества и даты в `tests/transit-catalog.test.js` привязана к текущему снимку; при осознанной замене обновите ожидаемые значения после просмотра diff.

## Интеграция и проверка

`map.js` импортирует `mountTransitPanel({host,city,reducedMotion})`; компонент возвращает `setMap(map|null)`, `setCity(city)`, `destroy()`. Используется существующий экземпляр MapLibre. Источники `transit-stops` / `transit-route` удаляются до удаления карты; панель и каталог работают при недоступном WebGL. События и API основной карты сохранены. CSP Node/Worker и static headers разрешают только дополнительный origin `https://overpass-api.de`.

Проверки на базе main `107186a`: **353/353 Node-теста прошли**, включая 18 тестов провайдера/каталога (отмена, таймаут, кэш, неполная геометрия, варианты букв, разделение городов); проверка архитектурных границ и CSP прошла. Chrome 1440 и 390 px: поиск 52/15A, выбор остановки и слоя, очистка при смене города, отсутствие горизонтального переполнения. Направления другого города и HTTP503 проверены контролируемыми ответами в браузере; это проверка клиента, не свидетельство покрытия другого города реальным API. Пограничные проверки подтвердили отсутствие загрязнения города запоздалыми snapshot/API ответами, очистку слоёв/listeners, поиск при заблокированной библиотеке карты и выключенном WebGL. Живой API подтвердил остановки Астаны и CORS отдельно.
