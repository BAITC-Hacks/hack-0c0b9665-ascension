Точные правила автоматического заполнения A/B уточнены в карточке H12-UI-02.

Интегратор добавляет в свой HTML:

```html
<link rel="stylesheet" href="/comparison.css">
<section id="comparison-panel"></section>
<script type="module" src="/comparison.js"></script>
```

Вход: событие `scenario:calculated` на `window`, `detail: { scenario: { decisions }, result }`.
После успешного расчёта основной UI отправляет его один раз. Первый результат записывается в A, второй в B; следующие сдвигают B в A и записываются в B. Хранятся только два последних независимых снимка в памяти страницы. Перезагрузка очищает их.

Выход: клик «Загрузить A/B» отправляет ровно одно `scenario:load` с `detail: { scenario }`. Отправляется новая глубокая копия исходного объекта, городским мерам не добавляется `districtId`. Валидацию, заполнение формы и последующий расчёт выполняет основной UI. Панель не вызывает HTTP/AI, не импортирует ядро и не пересчитывает Score.

При загрузке до готовности DOM модуль ждёт `DOMContentLoaded`; при отсутствии контейнера не падает. Повторное подключение к тому же контейнеру не создаёт второй интерфейс и обработчики. Контейнер должен существовать к моменту готовности DOM; динамическое добавление контейнера позже не входит в контракт.

Для каждой стороны показаны `score`, `totalCost`, `remainingBudget`, `criticalCount`, `worstDistrictScore`. Районы сопоставляются по `id`, используется `afterScore`. Все значения округляются только при отображении до двух знаков; B−A считается из исходной точности. Нет данных — явная подпись, не ноль. Все текстовые значения вставляются через `textContent`; стили ограничены `.comparison-*`.

`result.valid !== true`, отсутствующие/нечисловые метрики, повреждённые decisions/районы, повторные ID районов и некопируемые объекты отклоняются целиком. Старые результаты сохраняются, выводится доступное сообщение. Эта проверка структуры не заменяет серверную проверку правил симуляции.

## Как воспроизвести после интеграции

1. Подключить два файла и контейнер согласно разделу выше. Запустить приложение командой из README интегрированной ревизии. Зафиксировать её SHA.
2. Рассчитать официальный и экономный наборы, проверить показатели и загрузку A/B в реальную форму; затем рассчитать набор на 100 и проверить сдвиг.
3. Для изолированных проверок событий можно сформировать fixtures в корне проекта (вне отслеживаемых файлов):

```sh
node --input-type=module > /tmp/comparison-fixtures.json <<'JS'
import { simulate } from './src/core/simulator.js';
const sets = [
  [['M7','nura'],['M8','nura'],['M10','nura'],['M12'],['M5','saryarka']],
  [['M9','nura'],['M11','almaty'],['M10','esil'],['M12'],['M4','esil']],
  [['M1','nura'],['M2'],['M4','esil'],['M5','saryarka'],['M8','nura']],
];
console.log(JSON.stringify(sets.map(choices => {
  const scenario = { decisions: choices.map(([measureId, districtId]) =>
    districtId ? { measureId, districtId } : { measureId }) };
  return { scenario, result: simulate(scenario) };
})));
JS
```

На тестовой странице загрузить JSON и отправлять элементы массива через `window.dispatchEvent(new CustomEvent('scenario:calculated', { detail: fixture }))`. Проверки мутаций выполняются над исходным fixture после отправки; для теста отсутствия дублей нужно подсчитывать события `scenario:load`. Не добавлять временную страницу в общие файлы проекта.
