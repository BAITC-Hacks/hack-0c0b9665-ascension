## Источники и подтверждённые правила

Прочитаны 23.09.2026: [ТЗ, русская часть, страницы 2–3](https://drive.google.com/file/d/1oDZtYnBgbcn_Ii7vleP87hkARJ2HmbXl7Cw_rsCxqpo/view) и [«Датасет районов», страницы 1–5](https://drive.google.com/file/d/1Uc-GdGoKhDY-spu8V50-ZMm33t2CjYLP/view).
Поручение и границы: [карточка H12-UI-01](https://trello.com/c/b7R3Xtcj).
Контракт ядра сверён с `src/core/simulator.js`, `data/city.json` и `docs/acceptance.md` в `origin/main` на коммите `f922e79`.

- Данные синтетические; названия районов не превращают показатели в реальные городские измерения. Для всех пользователей одна исходная база и бюджет 100 условных единиц.
- Выбрать ровно 5 уникальных мероприятий из M1–M14, каждое максимум один раз, даже при разных районах. Не более 2 мер одного направления; требование «ровно одна мера каждого направления» отсутствует. Официальный пример имеет распределение 2/1/1/1.
- Для районной меры обязателен один из пяти районов. Городская мера применяется ко всем пяти районам, район для неё не указывается.
- Стоимость не больше 100; ровно 100 разрешено. Остаток не даёт бонуса к Score.
- M1+M3 запрещены независимо от районов. M4+M7 и M5+M13 запрещены только при совпадении района; в разных районах эти пары разрешены.
- Порядок решений не влияет на результат. Невалидный набор не получает числовой Score; причина возвращается валидатором.
- Все показатели направлены «больше = лучше», диапазон 0–100. Горизонт 8 кварталов; эффект меры умножается на `(8 − lag) / 8`, фиксированные синергии не масштабируются лагом. Итоговые показатели ограничиваются диапазоном 0–100.
- `Score = 0.7 × средневзвешенная оценка районов + 0.3 × оценка худшего района − число показателей строго ниже 40`. Ровно 40 не штрафуется. Округление до двух знаков применяется только при показе.
- LLM объясняет результат расчётного ядра, вклад мер и компромиссы; не вычисляет и не придумывает числа.

## Схема экрана и состояния

Сверху: название «Аким на 5 часов», заметная подпись «Учебная симуляция на синтетических данных», бюджет «100 / потрачено X / осталось Y» и счётчик «Выбрано N из 5». На узком экране эти значения остаются перед списком мер.

Основная область: каталог 14 мер с фильтром по пяти направлениям. Карточка меры содержит ID, название, направление, стоимость, тип «Район» или «Весь город», лаг и ожидаемые изменения показателей. Для отрицательного эффекта используется явный знак минус, а не только цвет. У районной меры — поле «Выберите район» без предвыбранного значения. У городской — подпись «Все 5 районов», поля района нет.

Рядом (на телефоне ниже): список выбранных решений с названием района, стоимостью, действиями «Изменить район» и «Удалить». Уже выбранную меру нельзя добавить повторно. Шестую меру и третью меру направления добавить нельзя; рядом с недоступным действием показана причина. Превышение бюджета и конфликты блокируют добавление; смена района также проходит валидацию. Не разрешать применение сценария через иной путь, если ядро возвращает ошибку.

Ниже: кнопка «Рассчитать сценарий». До 5 корректных решений недоступна, рядом текст причины (например «Выберите ещё 1 решение»). Блок ошибок содержит все причины, включая конфликтующую пару и район, и ссылки/фокус на соответствующие поля. Ошибки не стирают выбор. Поля имеют подписи, управление доступно с клавиатуры, изменение бюджета и ошибка объявляются через доступную область уведомлений.

Итог: базовый Score, новый Score, дельта; стоимость и остаток; изменения показателей по районам и вклад мер/синергий. Далее AI-объяснение: сильные стороны, риски, компромиссы и рекомендации. Пока объяснение загружается, числовой результат уже виден. При ошибке AI показывать «Объяснение недоступно — повторить», не подменять его выдуманным текстом. При изменении выбора предыдущий результат помечается устаревшим; поздний ответ AI для старого набора не заменяет объяснение нового.

## Вход, выход и граница интеграции

Исходные каталог, бюджет и районы получаем из `getDataset()`, стартовую оценку — из `getBaseline()`. Пустой выбор допустим как состояние редактирования, но не как сценарий для `simulate()`.

Вход ядра: `{ decisions: [{ measureId, districtId? }] }`. Значения районов: `esil`, `almaty`, `saryarka`, `baikonur`, `nura`. Для городской меры свойство `districtId` полностью отсутствует: не `null`, не пустая строка.

Пример входа из официального приложения:

```json
{
  "decisions": [
    { "measureId": "M7", "districtId": "nura" },
    { "measureId": "M8", "districtId": "nura" },
    { "measureId": "M10", "districtId": "nura" },
    { "measureId": "M12" },
    { "measureId": "M5", "districtId": "saryarka" }
  ]
}
```

`validateScenario()` возвращает `valid`, `errors` (с `message`, `code`, опциональным `decisionIndex`) и `totalCost`. Ошибку количества решений в незавершённом черновике показываем как подсказку; она всё равно блокирует итоговый расчёт. Стоимость нельзя считать из пользовательского ввода или текста карточек.

Успешный `simulate()` возвращает `score`, `baselineScore`, `deltaScore`, `totalCost`, `remainingBudget`, `districts`, `contributions`, `synergies`, а также составляющие Score. При `valid: false` числового результата нет. Для официального примера: стоимость 95, остаток 5, база 52.55768, результат 56.54307, дельта 3.98539 (показ: 52.56 → 56.54, +3.99).

Ядро использует `node:fs`, поэтому напрямую импортировать его в браузерный код нельзя. Транспортный адаптер и AI-endpoint согласуются с Азаматом; этот документ не вводит маршрут HTTP и не меняет сервер/ядро. LLM передаётся уже рассчитанный результат и выбранные меры. Числа на экране всегда из ядра.

## Ручная приёмка: 8 проверок

Обозначение `M7/Нура` означает одну меру с указанным районом, `M12/город` — без `districtId`. Все перечисленные наборы — тестовые сценарии на официальных синтетических данных, не реальные рекомендации городу.

1. **Одна база и бюджет.** Действия: открыть новый сценарий в двух независимых сессиях, в одной выполнить расчёт и начать новый сценарий → ожидается: обе сессии начинают с бюджета 100, одинаковых 5 районов и 14 мер, базового Score 52.56; новый сценарий не наследует эффекты предыдущего → фактический статус: **NOT RUN**, интерфейс отсутствует в проверенной базе.

2. **Ровно 5 уникальных мер.** Действия: собрать официальный пример из раздела выше, проверить 0, 4, 5 и попытку 6 решений; попробовать повторить M7 в другом районе → ожидается: только 5 уникальных мер позволяют расчёт, шестая и повтор блокируются с причиной; удаление возвращает состояние незавершённого выбора → фактический статус: **NOT RUN**.

3. **Район обязателен.** Действия: выбрать M7 без района, затем Нуру; при интеграционной проверке передать неизвестный districtId → ожидается: без района расчёт заблокирован с указанием поля; Нура снимает эту ошибку; неизвестный район отклонён ядром, числового Score нет → фактический статус: **NOT RUN**.

4. **Городская мера.** Действия: добавить M12 в официальный пример и рассчитать; проверить отправленные данные и C2 районов → ожидается: поле выбора района отсутствует, `districtId` не отправлен, M12 даёт C2 +4.375 каждому из пяти районов; синергия M10+M12 даёт B1 +2 только Нуре → фактический статус: **NOT RUN**.

5. **Лимит направления.** Действия: рассчитать официальный пример (две социальные меры); затем попробовать набор M7/Нура, M8/Нура, M9/Есиль, M10/Есиль, M12/город → ожидается: пример 2/1/1/1 разрешён без требования охватить все направления; три социальные меры запрещены независимо от достаточного бюджета (80) → фактический статус: **NOT RUN**.

6. **Граница бюджета.** Действия: выбрать M1/Нура, M2/город, M4/Есиль, M5/Сарыарка, M8/Нура (100); отдельно попытаться собрать M3/Нура, M5/Сарыарка, M7/Нура, M10/Есиль, M12/город (105) → ожидается: первый набор разрешён, остаток 0; второй блокируется с причиной «Превышение бюджета на 5», числовой Score не выдаётся. Остаток бюджета официального примера 5 не добавляет баллов → фактический статус: **NOT RUN**.

7. **Несовместимости и исправление.** Действия: проверить пары в пятиэлементных наборах ниже, затем изменить район второй меры локальной пары → ожидается: M1+M3 запрещены и в одном, и в разных районах; M4+M7 и M5+M13 запрещены в одном районе, но разрешены в разных; сообщение называет пару и причину, после исправления локальный конфликт исчезает → фактический статус: **NOT RUN**.
   - M1/Нура, M3/Есиль, M9/Нура, M10/Нура, M12/город: стоимость 84, глобальный конфликт; повторить с M3/Нура.
   - M4/Нура, M7/Нура, M10/Есиль, M12/город, M2/город: стоимость 87; исправить M7 на Есиль.
   - M5/Сарыарка, M13/Сарыарка, M9/Нура, M10/Нура, M11/Есиль: стоимость 85; исправить M13 на Алматы.

8. **Изменение результата и объяснение.** Действия: рассчитать официальный пример (95, Score 56.54307), затем заменить M8/Нура на M9/Нура и пересчитать → ожидается: набор остаётся валидным, стоимость становится 85, результат меняется; старые Score/AI-текст не выдаются за актуальные. Новое объяснение описывает замену поликлиники спорт-хабами, влияние на S1/S2/B1 и сохраняющийся риск низкого S2 Нуры; все числа согласованы с ядром. При недоступном AI остаётся честный статус ошибки и возможность повтора → фактический статус: **NOT RUN**.

## Что согласовать перед реализацией

Подтверждённые правила выше отделены от предложений по интерфейсу. Азамату нужно подтвердить транспортный контракт браузер ↔ ядро (ядро уже существует, endpoint ещё не закреплён), формат и поставщика AI-объяснения, зону файлов следующей UI-карточки и поведение повторного запроса. Платные вызовы и ключи этим документом не требуются. Эти вопросы не блокируют приёмку UX-документа, но должны быть решены до реализации интерфейса.
