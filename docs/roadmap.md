## 3. Обязательные правила симулятора

1. Бюджет — 100 условных единиц для всех. Остаток не даёт бонуса; ровно 100 допустимо.
2. Ровно пять уникальных мероприятий. Повтор одной меры даже в другом районе запрещён.
3. Доступны все пять направлений; максимум две меры одного направления. Минимум три направления получается автоматически. **Не заставляем брать по одной мере в каждом направлении:** официальный пример содержит две социальные меры и не содержит транспортной.
4. У районной меры выбран один существующий район. У городской в API `districtId` отсутствует; эффект применяется ко всем пяти районам.
5. M1 и M3 несовместимы в любых районах. M4/M7 и M5/M13 несовместимы только в одном районе.
6. Невалидный набор получает причину ошибки и не получает числовой Score. Ноль не заменяет отсутствие результата.
7. Порядок решений не меняет расчёт. Исходные данные, цены, эффекты и бюджет сервер берёт из своего каталога.
8. Все показатели уже ориентированы одинаково: больше — лучше. Повторно инвертировать пробки или качество воздуха нельзя.

### Точная модель

Горизонт — восемь кварталов. Лаги L=1/2/3/4 дают реализованную долю эффекта 0.875/0.75/0.625/0.5.

```text
I'[d,k] = clip(I[d,k] + sum(effect[m,k] * (8-L[m])/8) + synergy[d,k], 0, 100)
D[d] = sum(weight[k] * I'[d,k])
D_avg = sum(pop[d] * D[d])
N_crit = count(I'[d,k] < 40)
Score = 0.7 * D_avg + 0.3 * min(D[d]) - N_crit
```

| Показатель | T1 | T2 | E1 | E2 | S1 | S2 | B1 | B2 | C1 | C2 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Вес | .10 | .10 | .09 | .11 | .11 | .11 | .09 | .09 | .10 | .10 |

Доли населения: Есиль .27, Алматы .24, Сарыарка .20, Байконур .13, Нура .16. Синергии фиксированы, без лага: M1+M2 → T1+2 в районе M1; M10+M12 → B1+2 в районе M10; M5+M6 → E2+2 в районе M5. У M11 есть отрицательный эффект T1−2 до лага.

Считаем критические ячейки «район × показатель», строго ниже 40 после всех эффектов. Округляем только отображение. Дополнительное ограничение самого Score формулой не задано. Базовый Score — справочная точка, а не допустимый набор из нуля решений.

| Сценарий | Решения | Стоимость | Score | Критических |
|---|---|---:|---:|---:|
| База | Без действий, только точка сравнения | 0 | 52.55768 | 2 |
| A: официальный | M7/M8/M10 в Нуре; M12 город; M5 Сарыарка | 95 | 56.54307 | 0 |
| B: перенос школы | Как A, но M7 в Есиле | 95 | 55.29777 | 1 |

Для замены A выигрыш 0.66249 сопровождается потерей улучшения воздуха Сарыарки. Это лучшая проверенная одиночная замена в текущей реализации, а не глобальный оптимум городской политики.

Разные наборы могут дать одинаковый итоговый балл. Критерий ТЗ о влиянии выбора доказываем конкретными A/B, не добавляем искусственную уникальность Score. Из-за минимального районного балла и порогов нельзя без обоснования складывать «вклады мер в Score» как линейные независимые величины.

| UI | Читаемый бюджет/пять решений; ошибки сохраняют выбор; A/B; клавиатура; небольшой экран | Алишер + интегратор |

Команды существующей проверки: `npm test`, `node --check public/app.js`, `node --check public/comparison.js`, `npm start`. Не добавляем тесты, которые только повторяют реализацию. Новые проверки нужны для изменённого поведения, найденной ошибки или неподтверждённого обязательного пункта.

### Правило передачи и коммитов

1. Участник читает свою карточку и контракт, проверяет origin/status/личную Git identity. Не угадывает имя или email.
2. Работает в своей ветке и согласованных файлах. Фиксирует полезные завершённые шаги реальными коммитами.
3. Перед commit смотрит diff и staged diff; добавляет только свои файлы. Никаких пустых коммитов, фиктивного авторства и force-push.
4. Push своей ветки и PR. Формат передачи: карточка → результат → проверка и SHA → PR → ограничения → следующий шаг.
5. Азамат читает diff, сверяет ТЗ, источники чисел, API и доказательства; возвращает конкретные замечания либо интегрирует.
6. Merge сохраняет личные коммиты. После проверки общей сборки карточка получает DONE и переносится в СДЕЛАНО. До этого — REVIEW.

Подтверждённые содержательные коммиты: Азамат `f922e79`, `aba0ccc`, `b0776a1`, `e041ad5`; Алишер `66d7119`, `83aa63f`; Данияр `997808b`, принят через PR #5 с merge `efed164`. Эти записи фиксируют реальный вклад. Живой AI этим набором коммитов не подтверждён.

Вопросы жюри:

- **Где AI?** Модель объясняет готовые факты и компромиссы, как требует датасет; формула остаётся проверяемой. JSON-схема гарантирует структуру, но не истинность всех фраз — поэтому сверяем текст с расчётом.
- **Почему не по одной мере на направление?** Детальное приложение требует максимум две на направление; воспроизводим его официальный пример.
- **Это прогноз реальной Астаны?** Нет, это синтетическая учебная модель. Для практики потребуются реальные данные, калибровка эффектов и экспертная проверка.
- **Это оптимум?** Проверяются допустимые замены одной меры. Глобальный оптимум и безусловно лучшая политика не заявляются.
- **Что без интернета?** Расчёт и сравнение сохраняются; резервное пояснение явно помечено. Для проверки обязательного живого AI предоставляем работающий доступ отдельно.

| Сигнал | Действие |

| QA Данияра блокируется на доступе | Записать точную ошибку и передать Азамату; чистый локальный запуск и остальные независимые проверки продолжить |

| Ошибка математики | Приоритет перед оформлением: фиксированный воспроизводимый пример, исправление ядра, соответствующая проверка, пересчёт затронутых демо |

После сдачи потенциальное развитие: калибровка модели на разрешённых реальных данных, неопределённость эффектов, сценарии событий, оптимизация нескольких целей, сохранение командных сессий. Эти функции не заявляем реализованными.
