# Приватный перенос локальных обращений на сайт

Этот инструмент переносит сохранённые обращения JSON в существующий `Complaints` Durable Object (`city`) на https://ascension-city-map.azamatbreach.workers.dev. Он не публикует Worker, не останавливает процессы и не меняет режим Telegram. Использовать только проверенный интегрированный release SHA и согласованный оператором момент переноса.

## Что сохраняется

Каждая запись переносится целиком: ID, trackingToken, текст, адрес, координаты, Telegram chat/update/draft ID, ссылки на фото, анализ, даты и история. Ничего не пересоздаётся и не классифицируется заново. Полностью совпадающие записи повторно не записываются. Отличия по существующему ID, конфликт Telegram update ID или пары chat/draft отклоняют весь импорт. Посторонние записи, Telegram-сессии и журналы не удаляются.

Локальный JSON содержит `version: 1` и `complaints`. Он **не содержит** незавершённые диалоги и весь журнал обработанных Telegram updates: в локальном Node эти сведения находятся в памяти. Сначала нужно закончить активные диалоги и согласованно остановить локальные записи. Утверждение `--writers-stopped` — подтверждение оператора, а не автоматическая проверка процессов. Существующие сохранённые update/draft ID переносятся буквально; перенос полного журнала не заявляется.

Фото в базе — ссылки Telegram file_id, а не отдельный архив изображений. На хостинге должен быть настроен **тот же бот**. Панель акима получает изображения через защищённый photo API. Файл, отправленный в Telegram как document, этим механизмом не поддерживается.

## Включение на существующем Worker

Владелец публикации развёртывает согласованный SHA с этим кодом, сохраняя существующие bindings, миграции и секреты. Для временного маршрута нужны:

- `ADMIN_TOKEN`: действующий закрытый ключ панели.
- `COMPLAINTS_MIGRATION_TOKEN`: отдельный случайный секрет из 32–256 символов `A-Z`, `a-z`, `0-9`, `_`, `-`, отличный от ADMIN_TOKEN.

Секреты добавляются через Cloudflare Dashboard либо интерактивный `wrangler secret put`. Их нельзя помещать в аргументы CLI, Git, публичные комментарии или логи. Без двух независимых корректных секретов маршрут `/api/complaints/_migration` возвращает 404. Обычные администраторские маршруты это не открывает публично.

Сначала проверить `/api/citizen/config`: telegramConfigured, webhookConfigured и adminConfigured должны быть true. Убедиться, что публичные `/api/complaints` и photo API закрыты без административного ключа. До согласованного переключения действующий бот продолжает получать сообщения прежним способом.

## План → запись → проверка

Node.js 24+. Выполнять команды из корня проверенного checkout. Приватное окружение содержит `ADMIN_TOKEN`, `COMPLAINTS_MIGRATION_TOKEN` и при желании `COMPLAINTS_FILE` с абсолютным путём к снимку. Не копировать рабочие обращения в публичные assets или Git. CLI принимает только существующий HTTPS-адрес сайта и запрещает перенаправления.

1. Согласовать короткую остановку единственного polling и всех локальных writers после завершения диалогов. Не удалять очередь Telegram. Сделать приватную резервную копию и неизменяемый снимок действующего COMPLAINTS_FILE; счётчик из прежнего отчёта может быть устаревшим. Сохранить рабочий файл и резервную копию.
2. Выполнить plan для этого снимка. Он только читает данные на сервере и возвращает количество записей и хеши.

```sh
node --env-file=/private/migration.env scripts/migrate-complaints.mjs plan --file /private/complaints-snapshot.json
```

3. Сверить количество записей. Использовать возвращённый planDigest для commit того же снимка:

```sh
node --env-file=/private/migration.env scripts/migrate-complaints.mjs commit --file /private/complaints-snapshot.json --plan-digest <planDigest> --writers-stopped
```

Запись идёт атомарно и под той же очередью, что обычные изменения обращений. Если снимок или цель изменились после plan, commit возвращает конфликт; выполнить сверку и новый plan. При потере ответа повтор того же commit безопасен. Изменённая сотрудником запись никогда не откатывается старым снимком. Вместе с записями сохраняется служебная квитанция импорта: только хеши, количество и время.

4. Проверить результат:

```sh
node --env-file=/private/migration.env scripts/migrate-complaints.mjs verify --file /private/complaints-snapshot.json
```

Проверка сравнивает полное содержимое импортированного набора по хешу, проверяет старые квитанции и доступность фото, если они есть. В вывод попадают только безопасные итоги и хеши. Номера обращений, исходные тексты, токены и Telegram file_id не выводятся. Для большого числа квитанций проверка выполняется последовательно с ограничением частоты.

Размер снимка ограничен 5 MiB, максимум 1000 записей, не более 100 KiB на запись. Слишком большой или некорректный снимок отклоняется; автоматического разбиения с частичным импортом нет.

## Переключение и фактическая приёмка

После успешной проверки оператор согласованно включает hosted webhook для того же бота. Второй polling не запускать. Рабочие очереди Telegram не удалять. Код переноса сам не выполняет cutover.

На целевом сайте проверить новую явно тестовую заявку, отправленную **через настоящий Telegram**: согласие → описание и фото → проверка → отправка → квитанция. В защищённой панели должна появиться запись с тем же ID; изображение должно открываться через photo API. Затем проверить сохранность после перезапуска, старые квитанции и отсутствие второй заявки после повтора доставки. Тесты с подменой Telegram не заменяют эту приёмку.

После переноса удалить временный `COMPLAINTS_MIGRATION_TOKEN` из настроек Worker и приватного окружения: маршрут снова должен возвращать 404. Удаление секрета не удаляет обращения или квитанцию импорта. Сохранить приватную резервную копию по принятому порядку. Возврат к локальному режиму после появления новых облачных записей требует отдельного обратного переноса; простое включение старой локальной базы теряет новые данные.

## Протокол для оператора

`POST /api/complaints/_migration`, заголовки `X-Admin-Token`, `X-Complaints-Migration-Token`, `Content-Type: application/json`; без Origin. Тело: `{action:'plan'|'commit'|'verify', snapshot:{version:1,complaints:[...]}, planDigest?}`. Для commit хеш обязателен. Успешный ответ содержит только action, counts, sourceDigest, targetDigest, planDigest и признак verified для verify. Ошибка возвращает HTTP status и статический код в `X-Migration-Error`, без тела: это также позволяет отклонять неавторизованные загрузки без чтения тела запроса в Worker→DO. Shared публичный JSON parser и его лимит 32 KiB не менялись; обслуживание импорта использует отдельный ограниченный parser.

Транзакции используют стандартный [Cloudflare Durable Object storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#transaction).
