# Ascension AI: текстовый план города

`src/ai/plan.js` переводит намерение пользователя в меры официального каталога. Модель выбирает меры и качественно объясняет выбор. Бюджет, конфликты, численные эффекты и итоговый Score определяют только `validateScenario` и `simulate` из общего ядра.

## Серверный вызов

```js
import { proposePlan, MAX_PLAN_PROMPT_CHARS } from './ai/plan.js';

const plan = await proposePlan({ prompt }, {
  apiKey: serverSecret,
  model: configuredModel,
  // fetchImpl и timeoutMs необязательны; полезны для тестов.
});
```

Вход допускает только поле `prompt`: непустой текст до `MAX_PLAN_PROMPT_CHARS` (4000 символов). Чужие поля, включая присланные бюджет, стоимость и результаты, отклоняются до запроса к провайдеру. Пустой `apiKey: ''` явно отключает API; он не заменяется ключом из окружения. Если параметр не задан, используются серверные `OPENAI_API_KEY` и `OPENAI_MODEL`. Значение модели по умолчанию совпадает с существующим модулем объяснений.

Модуль не является HTTP-маршрутом. Владелец интеграции оборачивает его существующей защитой origin/размера тела и общим `AI_BUDGET` перед любым платным вызовом. Секрет и выбор модели остаются на сервере. Не разрешать клиенту передавать `options`, адрес провайдера или ключ. Дополнительных повторов при ошибках нет.

## Ответ

| Поле | Контракт |
| --- | --- |
| `mode` | `ai` для разобранного ответа модели, `unavailable` при недоступности или невалидном формате |
| `available` | Модель действительно вернула проверяемую структуру; это не означает допустимость плана |
| `reason` | При недоступности: `invalid_input`, `not_configured`, `rate_limited`, `provider_error`, `timeout`, `invalid_model_plan`, `refused`; при недопустимом плане: `invalid_plan` |
| `summary` | Короткое качественное объяснение без численных результатов модели |
| `decisions` | Массив `{ measureId, districtId? }`, совместимый с симулятором; у городской меры район отсутствует |
| `decisionOrigins` | `{ decisionIndex, source: 'requested' \| 'suggested', rationale }` для каждого решения |
| `unsupported` | Части запроса, которые отсутствуют в модели или требуют уточнения |
| `assumptions` | Допущения, ограничения синтетической модели; каждое дополнение ИИ также помечается здесь сервером |
| `valid` | И структурированный план, и весь запрос можно рассчитать в модели |
| `validation` | Результат `validateScenario`: `valid`, `errors`, `totalCost`; для неподдерживаемого запроса добавляется `UNSUPPORTED_REQUEST` |
| `result` | Присутствует только при `valid: true`; точный результат `simulate({ decisions })` |

Пустой либо частичный набор остаётся частичным: модуль не заполняет недостающие решения. Если пользователь запросил только школу, ядро вернёт `DECISION_COUNT`. При отсутствии района вернётся `DISTRICT_REQUIRED`, а также обратная связь модели. Бюджет, повторные меры, лимит направлений и несовместимости возвращаются с кодами общего валидатора.

Дополнения допустимы, когда пользователь попросил подобрать или дополнить план. Они всегда имеют `source: 'suggested'` и видимую строку `Дополнение Ascension AI: …` в `assumptions`. При невозможной, посторонней или неоднозначной идее модель должна вернуть ограничения, а не выдумывать успешное выполнение. Даже если оставшаяся часть содержит пять допустимых мер, непустой `unsupported` не позволяет вернуть `result` и выдать частичный ответ за полный.

Интерфейс должен показывать `summary`, `unsupported`, `assumptions`, происхождение дополнений и ошибки проверки; отрисовывать текст через `textContent`, не `innerHTML`. Числа и карту обновлять только из `result` при `valid: true`. `available: true` при `valid: false` означает, что ИИ разобрал запрос, но расчёт не прошёл. Данные остальных городов этот модуль не создаёт.

## Границы доверия и расходов

Используется Responses API с `text.format.type: 'json_schema'`, `strict: true` и ID мер/районов в `enum`. Поля модели всё равно проверяются повторно: запрещены неизвестные поля, ID, численные результаты в тексте и утверждения о гарантированном результате. Для городской меры провайдер передаёт `districtId: null`; перед расчётом поле удаляется. Районные меры с `null` не получают район автоматически.

Один вызов делает максимум один запрос на фиксированный адрес OpenAI. Предел ответа — 3000 токенов и 24 000 символов структурированного текста; отдельные поля и массивы также ограничены. Оболочка ответа читается потоком с пределом 64 КиБ до разбора JSON: превышение `Content-Length` или фактически прочитанных байт отменяет поток. Таймаут по умолчанию и сверху — 25 секунд, включая получение тела ответа. Запрос отменяется при таймауте. `store: false`, кэша пользовательских текстов нет. Тела ошибок провайдера не читаются и не возвращаются, сообщения исключений и ключи в ответ не попадают. Для простых внедрённых тестовых транспортов сохранена поддержка `json()` без потока; рабочий `fetch` использует ограниченное потоковое чтение.

Проверка структуры не доказывает точность понимания естественного языка: пользователь должен видеть выбранные меры, районы и допущения. Синтетические коэффициенты общего ядра не становятся реальным прогнозом вследствие подключения языковой модели.

Формат запроса согласован с [официальной документацией OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
