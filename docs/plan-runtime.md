# План и траектория: HTTP и допуск к AI

`POST /api/plan` принимает только `{ "prompt": "..." }`: непустой текст длиной до 4000 символов. Поля модели, ключа, таймаута и бюджета от клиента не принимаются. Общие проверки пути, метода, Origin, JSON, UTF-8 и 32 KiB выполняются до маршрута; проверка формы prompt — до допуска к провайдеру. Неверный prompt возвращает 400, не расходуя квоту.

Сервис планирования возвращает 200 и проверенный черновик. Только `mode: "ai"`, `available: true`, `valid: true` вместе означают готовый сценарий с `result`, рассчитанным официальным ядром. Частичное предложение имеет `valid: false`, ошибки проверки и не содержит результата. При отсутствии ключа, отказе квоты или провайдера ответ имеет `mode: "unavailable"`; это не выполненная симуляция. Причина и безопасное пояснение доступны интерфейсу, `Retry-After` сохраняется при временном ограничении.

`POST /api/trajectory` принимает стандартный сценарий `{ "decisions": [...] }`. Он не вызывает AI и не расходует его квоту. Невалидный сценарий возвращает 422 с ошибками официального валидатора; валидный — 200, исходное состояние в квартале 0 и точный официальный результат в квартале 8. Промежуточные кадры — явно обозначенное учебное допущение, описанное в [модели динамики](trajectory-model.md).

В каждом Node-сервере и экземпляре Worker создаётся один `ai-admission`, общий для `/api/plan` и `/api/explain`. У маршрутов нет независимых счётчиков. Worker сохраняет платформенный limiter, объект `AI_BUDGET.getByName('global')`, повторную локальную проверку после асинхронного limiter и освобождение permits в `finally`. Ошибка guard закрывает платный путь. Внешний вызов не повторяется при ошибке освобождения lease.

Планировщик не передаёт пользовательский текст в контракт сценария для пояснений. Оба сервиса получают только серверные параметры провайдера. Fallback получает явный пустой ключ, поэтому отключённое окружение не может случайно воспользоваться ключом процесса. Node сохраняет прежний кеш успешных пояснений только для стандартного провайдера с настоящим `process.env`; внедрённые окружения получают явные параметры. Worker сохраняет `skipReplacementSearch: true` для платного и резервного пояснения.

`tests/plan-http.test.js` проверяет оба runtime, смешанную квоту и одновременность, ошибки входа и неизменность официальных чисел. `tests/node-explanation-cache.test.js` проверяет кеш и отсутствие неявного заимствования ключа. Реальные ключи и платные вызовы для этих тестов не нужны.
