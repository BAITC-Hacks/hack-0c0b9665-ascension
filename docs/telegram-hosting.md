# Telegram: хостинг и локальный запуск

Целевой сайт: https://ascension-city-map.azamatbreach.workers.dev. Код поддерживает оба режима. Наличие файлов конфигурации или успешный dry-run не означает, что текущая версия уже опубликована: после deploy обязательно проверьте `/api/citizen/config` и `npm run bot:status`.

## Переключение

Если бот уже принимал реальные обращения локально, сначала выполните перенос по [плану передачи Азамату](azamat-telegram-handoff.md). Команды переключают доставку, но не копируют базу: без переноса старые квитанции на новом сервере не найдутся. Автоматический импорт в этой версии не реализован.

Команды выполняются из корня проекта, Node.js 24+. Токен и секрет берутся из игнорируемого `.env.local`.

| Задача | Команда |
|---|---|
| Запустить локальный сайт | `npm start` |
| Перевести бота на локальный сервер и запустить polling | `npm run bot:local` во втором терминале |
| Перевести бота на готовый хостинг | Остановить polling через Ctrl+C, затем `npm run bot:hosted` |
| Проверить способ доставки | `npm run bot:status` |

`bot:local` сначала проверяет работоспособность локального сервера и совпадение секрета, затем снимает webhook и начинает polling. `bot:hosted` сначала проверяет сервер и секрет на хостинге, затем регистрирует webhook с одним соединением. Обе команды сохраняют очередь ожидающих обновлений. `npm run bot` запускает только polling и отказывается работать при зарегистрированном webhook.

Один Telegram-бот не может одновременно использовать `getUpdates` и webhook. Для параллельных тестов используйте отдельного тестового бота и отдельное окружение. Сам сайт может работать локально одновременно с облачным ботом. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates).

## Настройки

Скопируйте недостающие имена из `.env.example`, не перезаписывая уже настроенный `.env.local`:

```dotenv
TELEGRAM_BOT_TOKEN=<токен из BotFather>
TELEGRAM_BOT_USERNAME=Ascension_City_bot
# Секрет: 1–256 символов из A-Z, a-z, 0-9, _ и дефиса.
TELEGRAM_WEBHOOK_SECRET=<случайный-секрет>
TELEGRAM_HOSTED_URL=https://ascension-city-map.azamatbreach.workers.dev
BOT_SERVER_URL=http://127.0.0.1:3001
PORT=3001
HOST=127.0.0.1
```

`BOT_SERVER_URL` должен совпадать с портом локального сервера. `TELEGRAM_HOSTED_URL` задаёт адрес облачного обработчика независимо от локального `PUBLIC_BASE_URL`. Если первая переменная пуста, команда использует `PUBLIC_BASE_URL`. `PUBLIC_BASE_URL` также задаёт ссылку проверки обращения в ответах бота. `TELEGRAM_SUPPORT_URL` — необязательный контакт поддержки.

## Первичная публикация на Cloudflare

Публикует один согласованный владелец из проверенного Git checkout. Конфигурация `wrangler.jsonc` сохраняет существующий `AIBudget` и добавляет `Complaints` отдельной SQLite-миграцией. Требуются права на существующий Worker `ascension-city-map` в аккаунте с поддоменом `azamatbreach`.

```sh
npx --yes wrangler@4.136.3 login
npx --yes wrangler@4.136.3 whoami
npm test
npx --yes wrangler@4.136.3 deploy --dry-run
npx --yes wrangler@4.136.3 deploy
```

Через Cloudflare Dashboard → Worker → Settings → Variables and Secrets добавьте серверные секреты:

- `TELEGRAM_BOT_TOKEN` — тот же бот, что локально.
- `TELEGRAM_WEBHOOK_SECRET` — тот же секрет, что локально.
- `ADMIN_TOKEN` — отдельный случайный ключ для панели акима; без ключа удалённая панель закрыта.

Значения можно ввести интерактивно через `npx --yes wrangler@4.136.3 secret put ИМЯ`. Не передавайте их аргументами команд, в Git, скриншотах или сообщениях. Сохраните существующий `OPENAI_API_KEY` и остальные настройки симулятора. Публичные `TELEGRAM_BOT_USERNAME` и `PUBLIC_BASE_URL` уже заданы в `wrangler.jsonc`; при необходимости добавьте `TELEGRAM_SUPPORT_URL`.

После публикации `/api/citizen/config` должен вернуть `telegramConfigured:true`, `webhookConfigured:true`, `adminConfigured:true`. Остановите прежний polling, выполните `npm run bot:hosted`, затем `npm run bot:status`. Webhook должен указывать на целевой домен и `/api/telegram/webhook`. Компьютер для работы бота больше не нужен. Проверка `POST {}` с правильным webhook-секретом проверяет обработчик без отправки кому-либо сообщения.

## Хранение и восстановление

Локально обращения остаются в `COMPLAINTS_FILE` или `var/complaints.json`. В облаке каждое обращение хранится отдельной записью Durable Object; операции сериализованы, изменения транзакционные. Панель `/mayor.html` требует облачный `ADMIN_TOKEN`, форма `/citizens.html` доступна жителям. Копирование локальной базы в облако автоматически не выполняется.

Облачные диалоги сохраняют черновик, шаг меню и последние подготовленные ответы между перезапусками. Черновик действует 30 минут бездействия. Идентификатор отправленного черновика и `update_id` предотвращают создание повторного обращения после сбоя; повторная доставка исходящего сообщения всё же возможна, если Telegram принял ответ непосредственно перед обрывом соединения. Очередь и квитанции не удаляются при переключении режима. Незавершённый диалог между локальной и облачной базами не переносится.

Бесплатный Render из `render.yaml` не является постоянным хранилищем обращений: для файлового Node-сервера нужен постоянный диск и один процесс. Для этого проекта подготовлен Cloudflare Durable Object. [Cloudflare: SQLite storage](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/).
