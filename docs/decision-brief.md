# Записка для совещания

Модуль превращает последний успешный серверный расчёт в короткую записку: выбранные пять мер и районы, расходы и остаток в условных единицах, Score до/после/изменение, критические показатели, худший район и ухудшения. Подробные таблицы, стоимость и лаг каждой меры, сочетания мер, источники и ограничения раскрываются отдельно. Название и цель можно ввести вручную: 100 и 500 символов соответственно.

Скачивание создаёт автономный HTML с полным текстом, тремя таблицами и стилями печати. Файл читается без приложения, внешних шрифтов, скриптов и сети; печать — штатным Ctrl+P / Cmd+P браузера. Кнопка не обещает создание PDF. Текст названия, цели и названия из датасета экранируются. Никакие поля объяснения, ключи или прочие дополнительные поля результата в снимок не копируются. Модуль не делает сетевых запросов и не хранит данные в localStorage.

## Подключение владельцем UI

Файлы модуля: `public/decision-brief.js`, `public/decision-brief.css`. Подключение в общие app/index/styles выполняет владелец интерфейса после принятия PR. Контейнер размещается рядом с результатом, а не в конце каталога мер.

```html
<link rel="stylesheet" href="/decision-brief.css">
<section id="decision-brief" class="model-only"></section>
```

```js
import { mountDecisionBrief } from './decision-brief.js';

// dataset: текущий ответ /api/dataset.
// currentCity: актуальный объект city:changed, включая hasScenarioData.
const disposeDecisionBrief = mountDecisionBrief(
  document.querySelector('#decision-brief'),
  { dataset, city: currentCity },
);

// При удалении панели/страницы:
disposeDecisionBrief();
```

При позднем подключении обязательно передать текущий город. Без `city.hasScenarioData === true` генерация и скачивание запрещены. Mount не восстанавливает ранее пропущенный расчёт из глобального состояния: следующий успешный расчёт заполнит записку. Повторный mount того же контейнера снимает прежние обработчики. `dispose` можно вызывать повторно; он удаляет DOM, обработчики и освобождает созданные URL файлов.

| Событие window | Поведение |
|---|---|
| `scenario:calculated`, `{scenario:{decisions},result}` | Проецирует только нужные поля в независимый снимок; разрешает экспорт при успешном полном результате и доступной модели города |
| `scenario:invalidated` | Удаляет снимок и отображённые цифры; запрещает скачивание |
| `scenario:load` | Сразу запрещает скачивание, до следующего серверного расчёта |
| Любой `city:changed` | Удаляет снимок, даже при возвращении к Астане; проверяет строгое `hasScenarioData === true` |
| Некорректный новый результат | Удаляет прежний снимок, сообщает о необходимости пересчитать |

Главное приложение отвечает за актуальность `scenario:calculated`: поздний ответ старого запроса после изменения плана или смены города не должен порождать это событие. В существующем контракте события нет номера запроса; модуль не может отличить такой ошибочно опубликованный ответ от нового расчёта. Новый успешный актуальный расчёт восстанавливает экспорт. Модуль не изменяет формулу и не перепроверяет допустимость плана вместо сервера.

## Достоверность

- Идентификатор `official-astana-v1` импортируется из существующего `scenario-library.js`; это имя набора модели, не хеш файла и не доказательство подлинности.
- Все оценки и изменения показателей берутся из `result`; названия, бюджет модели, лаги и стоимости мер — из `dataset`. Разница районных оценок — простое вычитание полученных `afterScore` и `beforeScore`. Формула Score в модуле отсутствует.
- Критические показатели перечисляются по правилу кейса: строго ниже 40; улучшившийся показатель может оставаться критическим. Ухудшения перечисляются отдельно по отрицательному `delta`. Совпавшие худшие районные оценки выводятся вместе.
- Горизонт и лаг описывают условное время модели, не календарные сроки строительства. Числа округляются только при выводе; дельта получена до округления, поэтому округлённые числа могут визуально различаться на 0,01.
- На экране и в файле явно: **«Учебная модель. Не прогноз для реальной Астаны»**. Нет реальных тенге, уверенности в процентах, адресов, назначенных ответственных или обещаний готовности к исполнению.
- Дата снимка — время получения результата; дата формирования файла указана отдельно. Это не дата реальных измерений. Данные организаторов синтетические; дата измерений и физические единицы показателей не заданы.
- Блок «Что НЕ подтверждено» перечисляет адреса/объекты, реальные цены и население, смету/мощность, реальные эффект/сроки, ответственных и календарный план.
- Источники: [ТЗ кейса №12](https://drive.google.com/file/d/1oDZtYnBgbcn_Ii7vleP87hkARJ2HmbXl7Cw_rsCxqpo/view), [официальный датасет районов](https://drive.google.com/file/d/1Uc-GdGoKhDY-spu8V50-ZMm33t2CjYLP/view). Ссылки повторяются в автономном файле, но сеть для чтения записки не требуется.

Будущий блок паспортов данных или готовности к исполнению требует отдельного согласованного контракта. В этой версии параметры evidence/context не принимаются и такие сведения не выдумываются.

### Приёмка после подключения

1. Открыть общую страницу на 390 px и выполнить официальный расчёт. Записка находится рядом с результатом; экран не требует прокрутки всего каталога для доступа к кнопке.
2. Проверить числа первого теста и пять человеческих названий. Раскрыть подробности: стоимость/лаг, районы, все показатели, источники и ограничения доступны.
3. Ввести HTML-подобные название и цель, скачать с клавиатуры. Открыть файл без сети: текст безопасен, все таблицы и предупреждения доступны, Ctrl+P печатает документ.
4. Изменить меру, загрузить другой сценарий или переключить любой город: прежнюю записку больше нельзя скачать. Возврат к Астане не восстанавливает её автоматически; повторный успешный расчёт восстанавливает.
5. Во время медленного расчёта сменить план/город и вернуться: главный UI не публикует старый ответ. Затем проверить свежий расчёт.
6. Проверить M11-компромисс из второго теста, чтобы убедиться, что ухудшение не скрывается ростом общего Score.

Готовность этого модуля к review не означает DONE: нужны интеграция владельцем UI и проверка объединённого пользовательского пути.
