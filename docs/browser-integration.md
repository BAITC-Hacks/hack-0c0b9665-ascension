# Поиск альтернатив и библиотека в общем интерфейсе

Интеграция использует модули `policy-options`, `policy-options-panel`, `scenario-library` и существующий экспорт сравнения. Расчётное ядро, правила бюджета и серверный AI не меняются.

## Поиск на устройстве

`src/browser/policy-options-worker.js` импортирует единственный `src/core/policy-options.js`, который использует официальный `src/core/simulator.js` и `data/city.json`. Сборщик включает эти четыре файла в `public/policy-options-worker.js`. Формула не поддерживается вручную второй копией; изменение исходного ядра требует пересборки.

`public/policy-options-client.js` предоставляет панели совместимый с fetch адаптер. Только явная кнопка поиска создаёт отдельный module Web Worker. Идентификатор сообщения связывает ответ с запросом; отмена, ошибка, таймаут 12 секунд и успешное завершение освобождают worker и слушателей. Нет сетевого запроса к `/api/policy-options`, AI или Cloudflare CPU для перебора. При недоступном Web Worker выводится понятная ошибка; интерфейс и серверный расчёт остаются доступны.

Отправляется `{requestId, scenario, limit:6}`, возвращается `{requestId, data}` или безопасная `{requestId,error:{code,message}}`. Ошибочный исходный сценарий даёт `valid:false` и адаптируется к HTTP-подобному 422. Числа в панели предварительные. «Загрузить вариант» передаёт только `scenario:load`; приложение валидирует и по кнопке заново рассчитывает его сервером.

## Воспроизводимая сборка

Готовый worker коммитится, поэтому `npm start` и `npm test` работают без установки dev-пакетов. Для разработки:

```sh
npm ci
npm run build:policy-worker
npm run check:policy-worker
```

Версия esbuild закреплена: 0.28.2, lockfile содержит целостность пакетов. Сборка использует `platform:browser`, `format:esm`, `target:es2022`, не допускает дополнительных исходников или внешних импортов. [esbuild API](https://esbuild.github.io/api/#build). `docs/evidence/policy-worker-build.json` содержит параметры, SHA-256 каждого входа и результата. Хеши нормализуют CRLF в LF для переносимости Git на Windows. `--check` повторно собирает и сравнивает содержимое без перезаписи; обычный `npm test` проверяет manifest и исполняет сохранённый bundle в изолированном JS-потоке.

## События и территория

Модули монтируются после загрузки датасета с текущим `city.hasScenarioData`. `scenario:calculated` содержит независимый снимок успешного серверного результата. `invalidateResult()` отправляет `scenario:invalidated`, очищая кандидаты сохранения и альтернатив. Смена территории за пределы модели также отменяет текущий результат, сохраняя сами решения плана. `city:changed` скрывает все `.model-only`, включая новые панели. Возврат к Астане требует повторного расчёта перед новым сохранением или поиском.

На мобильном экране закреплены переходы к карте, плану, результату и сравнению. На десктопе длинный план имеет собственную прокрутку в пределах высоты окна: кнопка расчёта доступна мышью. Бюджет подписан как условный бюджет модели, у Score указан учебный характер; эффекты имеют читаемые названия и задержку в кварталах.

- Реальный браузер, локальная сборка без ключа: официальный A 56.54307 → Web Worker проверяет 181 вариант, 117 допустимы, пять результатов → первый вариант загружается → сервер возвращает 57.20556 и стоимость 100.

Тест исполняет реальные функции приложения в VM; 1/1 PASS после исправления найденного на ревью состояния кнопки.

Предыдущие доказательства живого AI и карты — [map-verification.md](map-verification.md). Проверка выше относится к исходной frontend-интеграции. При объединении с новой защитой AI из PR13 перед публикацией требуется отдельная проверка живого ответа по обновлённому контракту.

При объединении страниц обращений сохранён согласованный интерфейс карты, конструктора, библиотеки и альтернатив. Отдельные `/citizens.html` и `/mayor.html` доступны по ссылкам навигации. Они проверяют `/api/citizen/config`: при отсутствии маршрута или недоступности сервиса показывают сообщение, отключают отправку, проверку статуса и вход в кабинет. Кнопка повторной проверки позволяет восстановить доступ после подключения сервиса; действующий Node API сохраняет прежнее поведение. Синтетическая регрессия покрывает отсутствие API, сетевую ошибку, некорректный ответ, восстановление и отсутствие отправки данных до доступности.
