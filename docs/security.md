# Безопасность и модель угроз

Приложение — публичный учебный симулятор с синтетическими данными. У него нет регистрации, авторизации и серверного хранилища личных сценариев. Доступность вычислений, целостность формулы, конфиденциальность серверного ключа и ограничение платных обращений — основные защищаемые свойства. Этот документ описывает реализованные меры и их пределы; он не является результатом внешнего аудита или сертификацией.

## Границы доверия

Недоверенными считаются HTTP-запросы, импортируемые файлы, браузерное хранилище, названия из географического поиска и ответы AI-провайдера. Сервер доверяет поставляемому набору `data/city.json` и своему коду. Браузер получает публичные данные и результат расчёта, но не ключ. Внешний провайдер получает синтетические факты выбранного сценария; никаких произвольных URL для серверного запроса API не принимает.

Посетитель может послать собственный HTTP-запрос без интерфейса, изменить JSON, заголовки и localStorage, отправить много параллельных запросов или попытаться вызвать API с другого сайта. Защита не предполагает честность такого клиента. Контроль инфраструктурного аккаунта, сборочного окружения и локальной файловой системы находится за пределами HTTP-модели угроз.

## Угрозы, меры и проверка

| Угроза | Реализованная мера | Проверка / граница гарантии |
| --- | --- | --- |
| Подмена цены, бюджета, Score или набора данных | Строгая валидация сценария и новый расчёт в общем API перед объяснением | Приёмочные тесты ядра, HTTP-тесты клиентских overrides, тесты фактов AI |
| Слишком большой или неверный запрос | 32 KiB по байтам потока, JSON media type, отказ от сжатого тела, фиксированные методы/маршруты | Тесты неверного JSON, media type, заявленного и потокового превышения размера |
| Чтение `.env` и исходников через статику | Проверка пути; в Node — проверка разрешённого корня и реального пути, включая symlink; Cloudflare Assets настроен на `public` | HTTP-тесты traversal, приватных файлов и MIME; содержимое `public` должно оставаться публичным |
| Утечка ключа или внутренних деталей в ошибке | Ключ только в серверном окружении; ошибки API сериализуются без stack/path; клиент видит только boolean готовности | Тесты приватности ключа, исключений и fallback; `aiConfigured` не подтверждает работоспособность провайдера |
| XSS через текст модели, импорт и поиск | Текст выводится через `textContent` либо escaping; импорт сохраняет проверенные решения и отбрасывает чужие Score/AI-текст; CSP ограничивает источники | Тесты импорта, review мест вставки DOM и браузерная проверка; CSP не заменяет escaping |
| Запросы из чужой браузерной страницы | POST проверяет `Origin` и `Sec-Fetch-Site`; JSON и отсутствие разрешающего CORS дополнительно ограничивают браузер | Общая HTTP-policy; запросы без browser headers разрешены для CLI, поэтому это не аутентификация |
| Расходование бюджета через AI API | Ограничения попыток, частоты и одновременности; для Cloudflare — обязательный постоянный бюджет до вызова провайдера | Тесты конкурентного допуска, отсутствующего/ошибающегося хранилища и перезапуска SQLite |
| Ошибка или зависание AI | Timeout, проверка структуры и размеров текстовых полей, детерминированное пояснение с честным режимом; слот освобождается в `finally` | Mocked transport/timeout/refusal/error tests; числа остаются результатом симулятора |
| Изменение политики только на одном хостинге | Общий `SECURITY_HEADERS` и автоматическая сверка с `public/_headers` | `node scripts/check-quality.js`; заголовки живого развёртывания проверяются отдельно |

## Платные обращения и доступность

Локальный Node guard хранит состояние в одном процессе. По умолчанию разрешены 100 попыток, 10 в минуту и 2 одновременно; конфигурация ограничивается допустимыми диапазонами. Перезапуск процесса сбрасывает эти счётчики, несколько процессов не разделяют их. Поэтому локальный лимит нельзя считать глобальным финансовым ограничением.

В Cloudflare все экземпляры обращаются к одному Durable Object `global`. `AIBudgetState.acquire()` атомарно проверяет и записывает допуск в SQLite: 100 попыток за время существования хранилища, 10 в минуту, 2 одновременно. Ошибка провайдера также расходует попытку. `release()` освобождает только одновременность; прерванное обращение занимает слот до истечения 65-секундной аренды. Проверка и запись выполняются в синхронной транзакции, до сетевого вызова. Семантика транзакций описана в [документации Cloudflare SQLite storage](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/).

Платформенный rate limiter и локальный guard — дополнительные барьеры. Ошибка обязательного rate limiter или постоянного бюджета запрещает платный вызов и оставляет расчётное пояснение. Локальный guard перепроверяет доступность после асинхронного обращения к платформе; конкурентные запросы не должны использовать устаревшее разрешение. Ошибка освобождения lease не вызывает повторный запрос к провайдеру.

100 попыток — лимит количества, а не суммы денег: стоимость зависит от модели и токенов. Анонимный пользователь способен израсходовать доступные попытки, после чего остальным останется детерминированное пояснение. Эти ограничения также не обеспечивают полную защиту вычислительного API от DoS. Для постоянного публичного сервиса нужны эксплуатационные лимиты, мониторинг и отдельное решение о доступе к платной функции.

## Браузер и внешние сервисы

CSP разрешает собственные скрипты, выбранные origins карты/поиска, `blob:` workers для карты и inline styles, необходимые текущему интерфейсу. `object-src 'none'` и `frame-ancestors 'none'` запрещают плагины и встраивание страницы; дополнительные заголовки включают `nosniff`, `no-referrer` и запрет камеры, микрофона и геолокации. Разрешённые `style-src 'unsafe-inline'` и `worker-src blob:` являются явными компромиссами текущей карты, а не строгой политикой без исключений. Назначение CSP описано в [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP).

Cloudflare `_headers` относится к статическим ответам; динамический Worker устанавливает заголовки сам. Поэтому оба пути проверяются отдельно и сверяются в CI, согласно [документации Static Assets headers](https://developers.cloudflare.com/workers/static-assets/headers/).

Карта и поиск обращаются к внешним сервисам непосредственно из браузера. Их операторы могут видеть сетевой адрес и запрос; работа карты зависит от доступности этих сервисов. Локальная библиотека сценариев доступна скриптам того же origin и пользователю устройства, не синхронизируется между устройствами и не предназначена для секретных или персональных данных. Повреждённое хранилище не очищается молча, ошибки записи не выдаются за успех.

## Проверки и эксплуатационные ограничения

`npm test` выполняет детерминированные проверки ядра, HTTP, AI fallback, квот и импорта без реального платного обращения. CI проверяет Node.js 24 на Windows и Linux, использует `contents: read`, отключает сохранение Git credentials и закрепляет сторонние actions полными commit SHA. Запуск тестов не доказывает отсутствие всех уязвимостей; браузер, фактические заголовки, внешний runtime и опубликованная версия требуют отдельной проверки.

Секреты задаются через окружение или секретное хранилище платформы. Значения не должны попадать в `public`, Git, логи запросов, экспорт сценария или документацию. При компрометации ключ нужно отозвать у провайдера и заменить в окружении; удаление файла из текущего checkout само по себе не удаляет секрет из истории.

В демо нет пользовательской идентификации, разграничения ролей, аудита действий пользователей или договорённостей об обработке персональных данных. Для реального муниципального применения также необходимы проверенные локальные данные и отдельная оценка модели. Текст AI остаётся недоверенным пояснением: проверка JSON-структуры не гарантирует фактическую правильность каждой формулировки.
