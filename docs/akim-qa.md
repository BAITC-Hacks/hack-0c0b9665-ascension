# Приёмка кабинета акима

Браузерный сценарий: `node tests/akim-ui.e2e.mjs`.

Проверено 23 сентября 2026 года: 15 сценариев проходят в Chrome через Playwright, ошибок JavaScript нет. Проверка использует временную SQLite-базу, временный порт и демонстрационные данные; рабочая база не читается и не изменяется.

## Что проверяет сценарий

1. Вход администратора через интерфейс кабинета.
2. Соответствие счётчиков сводки открываемым обращениям и поручениям.
3. Обращения без района, сохранение этого фильтра и безопасное отображение HTML-подобного текста.
4. Русский/казахский язык и сохранение фильтров после перезагрузки.
5. Ручное объединение и разъединение с сохранением оригинальных обращений.
6. Создание поручения: данные формы сохраняются после ошибки сервера; повторное нажатие не создаёт дубликат.
7. Изменение поручения, личный контроль, запрос отчёта.
8. Вход исполнителя, запрет самостоятельного подтверждения, отчёт с двумя загруженными фотографиями «до» и «после»; текст не теряется при загрузке.
9. Подтверждение результата руководителем и возврат на доработку с сохранением отчёта и истории проверки. Проверенные задачи исчезают из активного личного контроля.
10. Повторный вход после завершения сессии с сохранением открытого черновика.
11. Конфликт проверки: после обновления показан актуальный отчёт, а введённый комментарий сохранён.
12. Конфликт редактирования: сохраняются изменённые пользователем поля, а новые ответственный и срок другого участника не перезаписываются старыми значениями.
13. Выбор пяти мер, серверный расчёт, сохранение, сравнение, загрузка после перезагрузки; черновик сохраняется при переключении разделов. Проверяются официальный контрольный Score 56.54307 и стоимость 95, район загруженной меры и клавиатурный фокус.
14. Сводка за ровно семь календарных дней, историческая проверка после возврата задачи, пустой период, текущие просрочки, безопасный экспорт HTML со ссылками на источники и режим печати.
15. Все пять разделов и карточка поручения на экране 390 × 844 без горизонтального переполнения страницы.

Ошибки HTTP 503, 401 и 409 в выводе консоли ожидаемы: они специально вызываются в сценариях восстановления. Любая ошибка JavaScript приводит к ненулевому коду выхода.

## Запуск и артефакты

Нужен Node.js 24+ и установленный Playwright. На рабочем компьютере сценарий автоматически использует библиотеку из bundled runtime Codex и установленный Google Chrome. Для другого окружения можно передать `PLAYWRIGHT_MODULE` (путь к `playwright/index.mjs`) и `CHROME_EXECUTABLE` (путь к Chrome); иначе используется пакет `playwright` и его браузер.

Вывод содержит каталог со скриншотами и экспортированной сводкой HTML. Каталог можно задать переменной `AKIM_SCREENSHOTS`. Снимки основных экранов создаются в размере окна, чтобы мобильный экран оставался читаемым. Временная база удаляется после завершения.

Для отдельных проверок:

- `AKIM_DECISIONS_ONLY=1 node tests/akim-ui.e2e.mjs` — стенд модуля решений с настоящими API расчёта и сохранения.
- `AKIM_SCREENSHOTS_ONLY=1 node tests/akim-ui.e2e.mjs` — снимки начала сводки на компьютере и телефоне без повторения полного сценария.

Для роли `akim` применяются те же права руководителя, что для `admin`; серверные проверки ролей, версий и валидации находятся в `tests/akim.test.js`. Браузерная приёмка не проверяет реальную доставку сообщений жителю: бот в этом приложении не подключён.
