# Аким на 5 часов · Ascension

Симулятор городских решений для кейса №12 HackAlem AI. Он помогает сравнить, **куда направить ограниченный бюджет и как выбранные инициативы повлияют на разные районы**. Пользователь выбирает пять мероприятий, получает расчёт качества жизни, видит слабейший район и сравнивает варианты при одинаковых расходах.

В основе — учебный набор пяти районов Астаны, 14 мероприятий и бюджет 100 условных единиц. Карта показывает реальную географию, а показатели и эффекты мероприятий взяты из синтетической модели кейса. Результат позволяет проверить логику решения; он не является прогнозом для реального города.

**[Открыть публичное демо](https://ascension-city-map.azamatbreach.workers.dev)** — для симулятора не нужны регистрация, личный API-ключ или подписка. Публичная сборка может отличаться от текущего исходного кода; сохранённые подтверждения публикаций перечислены ниже. Воспроизводимый маршрут этого README относится к локальному запуску текущей версии: **«Попробовать на примере» → «Посмотреть результат»**.

| Что проверять | Маршрут после локального запуска |
| --- | --- |
| Выбор инициатив, бюджет, Score и карта | Главная `/`: «План решений», «Результат», «Районы», «Карта и слои» в нижней панели |
| Альтернативы одной меры, закрепление мер и защита показателя | «Инструменты» → «Альтернативы решений»; поиск на устройстве |
| Сравнение A/B и библиотека | «Инструменты» → «Сравнение сценариев» / «Мои сценарии» |
| Записка для совещания с выгрузкой HTML | «Инструменты» → «Записка по решению», после успешного расчёта |
| Черновики поручений, паспорта реализации и источников данных | «Инструменты» → «Поручения и исполнение» / «Паспорта данных»; ручные записи в данном браузере |
| Предложение плана и объяснение результата моделью | «Ascension AI» и панель результата; нужен серверный ключ владельца |
| Веб-обращение жителя и проверка статуса по квитанции | `/citizens.html` |
| Решение по обращению в панели акима | `/mayor.html`; без токена в стандартном локальном демо-режиме |
| Telegram-приём обращений | Дополнительная настройка собственного бота по инструкции ниже |

API обращений реализован для Node.js и Cloudflare Worker: локальное хранилище — JSON-файл, облачное — Durable Object. [Публичная форма](https://ascension-city-map.azamatbreach.workers.dev/citizens.html) и [панель акима](https://ascension-city-map.azamatbreach.workers.dev/mayor.html) были опубликованы в указанной ниже версии; HTTP 401 без служебного токена — ожидаемая защита панели. Весь маршрут «житель → сотрудник → решение» жюри может проверить локально без аккаунтов и ключей команды.

## Как запустить

Нужны **Node.js 24 или новее**, npm из его поставки и современный браузер. Для клонирования нужен Git; также можно скачать ZIP репозитория и открыть терминал в распакованной папке. Доступ к закрытому репозиторию выдаётся организаторами; самому приложению аккаунт не нужен.

```sh
git clone https://github.com/BAITC-Hacks/hack-0c0b9665-ascension.git
cd hack-0c0b9665-ascension
node --version
npm start
```

Откройте **[http://127.0.0.1:3000](http://127.0.0.1:3000)**. В текущей версии установка npm-пакетов и сборка для запуска не нужны: MapLibre уже включён в `public/vendor/`. Файл `.env.local` необязателен; сообщение о его отсутствии при первом запуске нормально. Остановка сервера — **Ctrl+C**.

Расчёты, сравнение сценариев и локальные обращения работают без ключей внешних сервисов. Без `OPENAI_API_KEY` используйте **«Попробовать на примере»** или соберите пять мер через **«План решений»**, затем нажмите **«Посмотреть результат»**. Поле **«Оценить мой план»** предназначено для предложения мер моделью и требует настроенного AI; для ручного маршрута оно не нужно. Числа рассчитываются сервером, а объяснение без ключа помечается **«Без AI · расчётное объяснение»** — это текст по правилам, не LLM-анализ.

Для подложки карты и поиска нужен интернет, для 3D — поддержка WebGL. Если карта не загрузилась, расчёт и таблица показателей остаются доступны. **[Компактный симулятор](http://127.0.0.1:3000/classic.html)** использует то же ядро: план и результат находятся на одной странице, дополнительные инструменты раскрываются ниже. Переход к нему с главной — **«Инструменты» → «Компактный симулятор»**.

Если порт 3000 занят, создайте в корне `.env.local` со строкой `PORT=3001`, перезапустите сервер и откройте `http://127.0.0.1:3001`. Остальные необязательные настройки перечислены в [.env.example](.env.example). По умолчанию сервер слушает только `127.0.0.1`.

[Подробная инструкция самостоятельного запуска](docs/self-hosting.md) включает чистую проверку, постоянный сервер Linux с systemd, Docker Compose, HTTPS и резервную копию обращений. Для собственного сервера и бота используются собственные настройки владельца; базовая локальная проверка не требует облачной инфраструктуры.

## Как проверить решение за 5 минут

Шаги ниже описывают главную страницу `/`. На `/classic.html` кнопки загрузки примера и расчёта называются так же; вместо нижней панели раскройте **«Что можно улучшить в плане»** для альтернатив и **«Сравнить два последних расчёта»** для сравнения. Библиотека, записка, поручения и паспорта находятся в одноимённых раскрывающихся разделах.

### 1. Рассчитать официальный пример

На главной странице нажмите **«Попробовать на примере»** в верхней панели. Откроется конструктор с готовыми пятью мерами; в блоке **«Ваш план»** нажмите **«Посмотреть результат»**. Панель результата откроется после расчёта; позднее её можно открыть кнопкой **«Результат»** внизу. В плане должны быть:

| Мера | Район |
| --- | --- |
| M7 — школа и детсад | Нура |
| M8 — центр семейного здоровья / поликлиника | Нура |
| M10 — освещение и камеры | Нура |
| M12 — единая цифровая платформа обращений | Весь город |
| M5 — перевод частного сектора на чистое топливо | Сарыарка |

Проверьте результат по таблице. Точка в точных значениях ниже — десятичный разделитель; интерфейс использует запятую и округляет до двух знаков.

| Показатель | До решений | Официальный пример A | Вариант B из следующего шага |
| --- | ---: | ---: | ---: |
| Общий Score | 52,56 | **56,54** | **55,30** |
| Изменение Score | — | +3,99 | +2,74 |
| Стоимость / остаток | 0 / 100 | **95 / 5** | **95 / 5** |
| Критических показателей | 2 | **0** | **1** |
| Оценка слабейшего района, Нуры | 49,18 | 52,96 | 51,86 |

Точные контрольные Score: `52.55768`, `56.54307`, `55.29777`. В блоке **«Дополнительный эффект сочетаний»** видно совместное действие M10 и M12 в Нуре.

### 2. Сравнить решение при том же бюджете

Откройте **«План решений»** внизу. В блоке **«Ваш план»** у школы и детсада поменяйте район **Нура → Есиль**, остальные решения оставьте прежними. Снова нажмите **«Посмотреть результат»**: получится вариант B из таблицы. Стоимость остаётся 95, но один показатель Нуры остаётся ниже критической границы.

Откройте **«Инструменты» → «Сравнение сценариев»**. Сравнение показывает два последних расчёта; оценка Есиля меняется на **+1,10**, Нуры — на **−1,10**. **«Загрузить A»** возвращает решения первого варианта в форму — после загрузки откройте **«План решений»** и выполните расчёт заново. **«Скачать сравнение (JSON)»** сохраняет снимки A/B для передачи и воспроизведения.

В **«Инструменты» → «Мои сценарии»** укажите название и нажмите **«Сохранить расчёт»**. План можно загрузить после перезагрузки страницы или импортировать из JSON сравнения. Библиотека хранит до 20 сценариев в этом браузере на этом адресе; сравнение двух последних расчётов — в памяти вкладки. Импортированные оценки не принимаются за результат сервера: загруженный план нужно пересчитать.

### 3. Найти альтернативу одной мере

Заново нажмите **«Попробовать на примере» → «Посмотреть результат»**. Откройте **«Инструменты» → «Альтернативы решений»**, затем **«Найти альтернативы»**. Для официального примера без дополнительных ограничений поиск проверяет 181 замену, из которых 117 допустимы, и показывает пять вариантов с разными компромиссами между Score, слабейшим районом и расходами.

**«Загрузить вариант 1»** заменяет M5 в Сарыарке на M3 в Нуре. Откройте **«План решений»** и нажмите **«Посмотреть результат»**: ожидаются стоимость **100**, остаток **0** и Score **57,21** (точно `57.20556`). Предварительный поиск выполняется в Web Worker на вашем устройстве по общему ядру; загруженный вариант заново проверяет сервер. Поиск охватывает замену одного решения и не обещает глобального оптимума. [Границы поиска](docs/policy-options.md).

Для отдельной проверки ограничений снова рассчитайте официальный пример. В панели альтернатив раскройте **«Что обязательно сохранить»**, закрепите M5 в Сарыарке и защитите E2 в Сарыарке от ухудшения. Повторите поиск: будет проверено **144** замены, **86** допустимы, показано **6** из **7** вариантов Парето. Первый вариант сохраняет M5 и меняет M12 на M14; после загрузки и серверного расчёта ожидаются **56,64** и стоимость **97**. Защита сравнивает показатель с результатом текущего плана. Перед повторением поиска без ограничений снимите закрепление и защиту. [Приоритеты поиска](docs/policy-priority-constraints.md).

### 4. Проверить ограничения

Заново нажмите **«Попробовать на примере»**. Пока выбраны все пять мер, добавить шестую нельзя. В блоке **«Ваш план»** удалите **«Освещение и камеры»** (M10): останутся четыре меры стоимостью **83**. В направлении **«Транспорт»** попытайтесь добавить **«Умные светофоры»** (M2, стоимость 22). Набор на **105** не принимается, выбор остаётся **4 из 5**, кнопка **«Посмотреть результат»** недоступна. Сервер также отклоняет такой набор: `POST /api/simulate` возвращает HTTP **422** с ошибкой и без нового Score.

### 5. Проверить карту и объяснение

Верните официальный пример и выполните расчёт. Откройте **«Карта и слои»** внизу, переключите показатель и состояние до/после, выберите район и режим 3D. Таблица значений доступна через **«Районы»**. В компактном симуляторе раскройте **«Карта города»** и **«Показатели районов»**. При выборе другого города доступна география, а показатели Астаны скрываются: датасетов других городов в модели нет.

Движущиеся машины на карте — обозначенная в интерфейсе **симуляция транспорта**. Это анимация, а не GPS-позиции, реальные дорожные измерения или прогноз времени прибытия.

Откройте **«Результат»** и в блоке **«Почему получился такой результат»** проверьте обозначение режима. Итог выбранного сценария вычисляется сервером; числа в панели альтернатив предварительно рассчитываются на устройстве. Доступная модель даёт AI-анализ; без ключа, при лимите или ошибке провайдера остаются рассчитанные числа и явно обозначенное расчётное объяснение. Отсутствие живого ответа модели не мешает повторить числовую проверку, но не подтверждает критерий живого AI-анализа.

## Дополнительная проверка: материалы для принятия решения

После расчёта официального примера откройте **«Инструменты»**. Доступны следующие действия:

1. Выберите **«Записка по решению»**. В блоке **«Записка для совещания»** при желании раскройте **«Название и цель записки (необязательно)»**, заполните поля и нажмите **«Скачать записку»**. Полученный HTML открывается самостоятельно, без сервера и сети, содержит пять мер, результат **56,54**, бюджет **95 / 5** и ограничения модели. Печать — через браузер; файл не требует запуска скриптов. После изменения плана сначала выполните новый расчёт. [Состав записки](docs/decision-brief.md).
2. Перейдите к **«Поручениям и исполнению»** и нажмите **«Создать черновик поручений»**: появятся пять записей по выбранным мерам. Заполните тестового ответственного, срок и критерий проверки, выйдите из поля и перезагрузите страницу: ручные изменения сохраняются при редактировании. В паспорте реализации можно отдельно указать CAPEX/OPEX в тенге и период OPEX. Эти сведения не меняют стоимость в условных единицах и Score учебного сценария. Реестр хранится в браузере и не отправляет поручения реальным службам. [Реестр и паспорта](docs/action-register.md).
3. В **«Паспорта данных»** раскройте **«Посмотреть паспорт модели и добавить источник»**. Заполните тестовое наблюдение, оставьте **«Проверка человеком» = «Нужно проверить»** и нажмите **«Сохранить паспорт»**. Его можно выгрузить через **«Скачать паспорта»**. Такие записи хранятся отдельно от официального учебного датасета и не подставляются в расчёт. Заполнение паспорта само по себе не подтверждает достоверности наблюдения. [Паспорта источников](docs/evidence-register.md).

При переходе к другому городу расчётные панели и записка скрываются. Ранее сохранённые поручения остаются доступными, а создание нового набора требует свежего расчёта модели Астаны. [Проверка общего рабочего маршрута](docs/operator-integration.md).

## Дополнительная проверка: обращения жителей

Выполняйте после локального `npm start`, используя вымышленные данные.

1. Откройте **[страницу жителя](http://127.0.0.1:3000/citizens.html)**. Введите, например: «Тестовое обращение: во дворе не работает освещение», укажите район и тестовый адрес. Подтвердите согласие формы и нажмите **«Отправить обращение»**. Геолокация не обязательна; фотографии предусмотрены в Telegram-пути.
2. Сохраните выданные **номер и личный код проверки**. Они нужны для просмотра статуса.
3. Откройте **[панель акима](http://127.0.0.1:3000/mayor.html)**. В стандартном локальном режиме токен не нужен. Найдите обращение, заполните **«Ответственный»**, установите статус **«В работе»** и нажмите **«Сохранить изменения»**. Затем выберите **«Решено»**, заполните **«Решение / результат»**, например «Тестовая проверка выполнена», и сохраните.
4. На странице жителя проверьте статус по номеру и коду: должны отображаться новое состояние и решение. Перезапустите сервер — отправленное обращение должно сохраниться.

Категория, приоритет и возможные повторы здесь определяются **локальными правилами**, которые сотрудник может исправить. AI симулятора не выполняет анализ обращений. Обращения не меняют исходные показатели районов.

Локальные данные сохраняются в `var/complaints.json`, вне публичной статики и Git. Один файл обслуживает один процесс сервера; другой путь задаётся через `COMPLAINTS_FILE`. Публичный Worker использует отдельный Durable Object `Complaints`: локальные и облачные обращения автоматически не синхронизируются. При удалённом доступе к панели требуется серверный `ADMIN_TOKEN`; без него разрешено только локальное демо. Подробности: [контракт обращений](docs/citizen-contract.md), [проверки модуля](docs/citizen-verification.md), [безопасность](docs/security.md).

Для дополнительного Telegram-пути создайте собственного бота и задайте в `.env.local` `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `TELEGRAM_WEBHOOK_SECRET`. При уже работающем `npm start` откройте второй терминал и выполните `npm run bot:local`: команда проверит сервер, снимет webhook этого бота и запустит polling. `BOT_SERVER_URL` должен указывать на ваш сервер; в `.env.example` указан `http://127.0.0.1:3000`. В приватном чате бота: `/start` → новое обращение → согласие → описание → просмотр → отправка.

`npm run bot:status` проверяет способ доставки. Для переключения на собственный HTTPS-хостинг остановите polling, задайте `TELEGRAM_HOSTED_URL` своего сервера и выполните `npm run bot:hosted`. Polling и webhook одновременно не работают; переключение не переносит ранее принятые обращения между хранилищами. [Режимы запуска и настройки](docs/telegram-hosting.md), [меню бота](docs/telegram-ux.md).

В сохранённой проверке публичного [@Ascension_City_bot](https://t.me/Ascension_City_bot) webhook был зарегистрирован на `/api/telegram/webhook`, очередь была пуста, ошибка доставки отсутствовала. Полный диалог `/start → обращение → ответ сотрудника` этой проверкой не подтверждён. Старые локальные обращения в облако автоматически не перенесены.

## Технологии и устройство

| Компонент | Технология и назначение |
| --- | --- |
| Локальный сервер | Node.js 24+, встроенные HTTP и файловые API, JavaScript ES modules |
| Интерфейс | HTML, CSS, браузерный JavaScript; сценарии, черновики поручений и паспорта в браузере; самостоятельный HTML-экспорт записки |
| Расчёт | Общее детерминированное ядро `src/core/simulator.js` и фиксированный `data/city.json` |
| Поиск альтернатив | То же ядро в браузерном Web Worker; esbuild **0.28.2** только для пересборки |
| Карта | MapLibre GL JS **5.24.0**, OpenFreeMap / OpenStreetMap, поиск Photon |
| AI-объяснение | OpenAI Responses API, модель по умолчанию **`gpt-6-astra`**, строгий формат ответа |
| Публичный симулятор | Cloudflare Workers; постоянная общая квота AI в Durable Object |
| Обращения и бот | Node.js с JSON-файлом или Cloudflare Worker с Durable Object `Complaints`; Telegram Bot API; общий модуль `src/complaints/` |
| Проверки | Встроенный `node:test`; проверка синтаксиса и границ модулей; GitHub Actions для Node 24 |

Путь расчёта: **браузер → HTTP API → проверка плана → расчёт по данным кейса → числовой результат → отдельное объяснение**. Node.js и Cloudflare Worker используют общий API-слой. Клиент не подменяет датасет или формулу; запрос объяснения также проходит повторный серверный расчёт. [Архитектура](docs/architecture.md), [контракт интеграции](docs/integration-contract.md), [развёртывание](docs/hosting.md).

## Формула и роль AI

Нужно выбрать ровно **пять уникальных мер**, не более двух из одного направления, общей стоимостью не выше 100. Для районной меры выбирается район. M1/M3 несовместимы в любом месте; M4/M7 и M5/M13 — в одном районе. Эффект меры учитывает задержку: `(8 − lag) / 8`; фиксированные синергии добавляются отдельно. Показатели ограничены диапазоном 0–100.

В кратком ТЗ перечислены пять направлений, что можно прочитать как требование выбрать по одной мере из каждого. Детальное приложение «Датасет районов» задаёт другое правило: ровно пять мер, не более двух в направлении, то есть минимум три направления; его официальный пример не включает транспорт. Валидатор следует **детальному приложению**: все пять направлений доступны, но охватывать каждое в одном плане не обязательно.

```text
Score = 0.7 × средняя оценка районов с весами населения
      + 0.3 × оценка самого слабого района
      − число значений «район × показатель» строго ниже 40
```

Оценка района — взвешенная сумма его показателей. Неиспользованный бюджет не даёт дополнительных баллов. [Официальные значения и правила в тестах](tests/simulator.acceptance.test.js), [независимый целочисленный расчёт и сверка всего каталога с приложением](tests/dataset-contract.test.js).

Для объяснения модель получает готовые факты и описывает компромиссы. Числовая сводка и допустимые рекомендации формируются сервером; качественный текст модели всё равно следует сверять с таблицей. В отдельном режиме **«Ascension AI» → «Оценить мой план»** модель предлагает меры из каталога: проверьте предложение и нажмите **«Применить и показать»**, чтобы применить его после серверной валидации. Модель не назначает реальные поручения. [Граница доверия AI](docs/ai-grounding.md).

Для собственного AI-режима владелец сервера задаёт `OPENAI_API_KEY` и, при необходимости, `OPENAI_MODEL` в игнорируемом `.env.local`. В публичном демо ключ хранится в серверном секрете; посетитель его не вводит. Ожидание ответа ограничено 25 секундами. Общая квота публичного демо — 100 допусков к модели, до 10 в минуту и двух одновременно; ошибки провайдера также расходуют допуск. После исчерпания квоты работает расчётное пояснение.

Локальное объяснение может использовать проверенную замену одного решения. Это поиск среди соседних вариантов, без гарантии глобального оптимума. В серверном объяснении Cloudflare Worker такой перебор отключён; это явно указано в ответе. [Сохранённая проверка живого публичного AI от 23 сентября](docs/evidence/public-ai-smoke.json) относится к версии на момент проверки и не гарантирует наличие свободной квоты сейчас.

Следующие записи — **история проверок конкретных публикаций**, а не подтверждение развёртывания текущего исходного кода или доступности сервисов сейчас. Новый главный экран с выдвижными панелями и `/classic.html`, описанный в маршруте выше, нужно проверять локально; эти записи не подтверждают его публикацию.

## Автоматическая проверка

[Аудит по документам организатора и проход искусственного пользователя](docs/criteria-user-audit.md) содержит контрольные результаты, найденные проблемы и границы проверки публичной и локальной версий.

В корне репозитория выполните:

```sh
npm test
node scripts/check-quality.js
npm run test:self-host
```

Ожидаемый итог — все проверки проходят, команды завершаются с кодом 0. Тесты проверяют официальные числа, ограничения бюджета и совместимости, HTTP-контракты, безопасный импорт, fallback AI, обращения и Telegram. `test:self-host` отдельно проверяет чистый запуск и сохранение обращения после реального перезапуска, используя временный каталог и вымышленные данные. Внешние AI/Telegram-вызовы в автоматических проверках заменены подставными ответами: тесты не требуют ключей и не подтверждают доступность живых сервисов. Проверку пользовательского пути выполняйте по шагам выше.

Готовый браузерный Worker включён в репозиторий. **Только для его пересборки после изменения расчётного ядра или данных** установите dev-зависимости и выполните:

```sh
npm ci
npm run build:policy-worker
npm run check:policy-worker
```

Проверка сравнивает сборку с сохранённым файлом; для обычного `npm start` эти команды не нужны. [Сборка и интеграционные проверки](docs/browser-integration.md).
