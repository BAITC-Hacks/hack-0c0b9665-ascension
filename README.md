# Аким на 5 часов

**Публичное демо:** https://ascension-city-map.azamatbreach.workers.dev — карта, симулятор и серверный AI без входа посетителя. Развёрнуто на Cloudflare Workers; [проверка публичного AI](docs/evidence/public-ai-smoke.json), [проверки карты и публикации](docs/map-verification.md).

Симулятор решений для кейса №12 HackAlem AI. Выберите пять городских мероприятий в пределах бюджета 100 и увидьте, как они меняют показатели пяти районов, Astana Quality of Life Score и положение самого слабого района. Данные и эффекты синтетические: это учебная модель, не прогноз для реальной Астаны.

Интерактивная карта показывает реальные улицы и здания, поддерживает 2D/3D, выбор городов и регионов Казахстана и поиск других территорий. В Астане карта связана с учебными показателями районов: можно выбрать показатель, сравнить до/после и перейти к мерам для выбранного района. За пределами Астаны доступна география; показатели и симуляция скрыты, поскольку данных этих территорий в кейсе нет.

## Запуск за минуту

Требуется **Node.js 24+**. Для локального запуска установка npm-пакетов не нужна. MapLibre поставляется в `public/vendor/`; подложке карты и поиску требуется интернет. Расчётный модуль работает без внешних сервисов.

```sh
git clone https://github.com/BAITC-Hacks/hack-0c0b9665-ascension.git
cd hack-0c0b9665-ascension
npm start
```

Откройте **http://127.0.0.1:3000**. Для доступа к приватному GitHub нужен разрешённый организаторами аккаунт; скачанный исходный код запускается без входа в приложение, подписок или ключей. Калькулятор и проверенные рекомендации работают локально. При отсутствии подключения модели интерфейс явно показывает «Расчётное пояснение»; этот режим не выдаётся за LLM-анализ.

Дополнительные страницы обращений: **http://127.0.0.1:3000/citizens.html** для жителей и **http://127.0.0.1:3000/mayor.html** для акима. Житель отправляет текст и место проблемы, сохраняет номер и личный код проверки; аким фильтрует обращения, исправляет рекомендации, назначает службу и публикует решение. Обращения сохраняются между перезапусками. Этот модуль не меняет расчётные данные симулятора.

Для проверки логики и HTTP:

```sh
npm test
```

Если порт занят, задайте `PORT` в `.env.local`. Сервер по умолчанию слушает только `127.0.0.1`. Остановить: Ctrl+C.

## Сценарий проверки

1. Нажмите кнопку официального примера, затем расчёт. Будут выбраны M7, M8, M10 в Нуре, M12 для всего города и M5 в Сарыарке.
2. Стоимость **95**, остаток **5**; базовый Score **52.56**, результат **56.54**, прирост **3.99**. Критических показателей становится **0** вместо **2**. Срабатывает синергия M10 + M12.
3. Перенесите M7 из Нуры в Есиль и пересчитайте: стоимость остаётся **95**, Score становится **55.30**, один показатель Нуры остаётся критическим. Видно, почему выбор района важен даже при одинаковом бюджете.
4. Попробуйте выбрать шестую меру, несовместимую пару или набор дороже 100. Ошибка не должна получать числовой Score; выбор не теряется.
5. Прочитайте объяснение. При подключённой модели оно помечено как AI-анализ. Если провайдер недоступен, числовой результат сохраняется, а расчётное пояснение обозначено отдельно.
6. В панели «Сравнение сценариев» остаются два последних расчёта A/B с разницей оценок районов. «Загрузить A» возвращает первый выбор в форму; пересчёт создаёт новый результат. Снимки хранятся только до перезагрузки страницы.
7. На карте переключите «До решений / После решений» и слой показателя. Выберите район — блок приоритетов и район для новых мер обновятся. Кнопка «Подобрать меры» открывает нужное направление.
8. Переключите карту в 3D и приблизьте к зданиям. Выберите Алматы или область: учебные показатели Астаны исчезнут. Поиск по кнопке «Найти» позволяет открыть другую территорию; «Вернуться к модели Астаны» восстанавливает сохранённый в памяти план.

Точные контрольные значения: база `52.55768`; официальный пример `56.54307`; перенос M7 в Есиль `55.29777`. Округление используется только в интерфейсе.

## Правила модели

- Ровно пять уникальных мероприятий из 14. Не более двух из одного направления: необязательно брать по одной мере каждого направления.
- Для районной меры нужен район. Для городской `districtId` отсутствует; эффект применяется ко всем пяти районам.
- Стоимость не больше 100. Неиспользованный бюджет баллов не даёт.
- M1 и M3 несовместимы в любых районах. M4/M7 и M5/M13 несовместимы только в одном районе.
- Эффект меры умножается на `(8 − lag) / 8`. Синергии фиксированные, без уменьшения на лаг. Показатели ограничены диапазоном 0–100.
- Оценка района — сумма взвешенных показателей. Городской Score:

```text
0.7 × средняя оценка с весами населения
+ 0.3 × оценка самого слабого района
− число показателей «район × показатель» строго ниже 40
```

Исходный датасет и формулу клиент менять не может. Сервер заново валидирует и рассчитывает каждый запрос, включая запрос объяснения. Порядок решений не влияет на результат.

## AI-анализ

Серверный модуль вызывает OpenAI Responses API со строгой JSON-схемой. Модель получает выбранные меры, готовые показатели, вклад мер, синергии, слабейший район и, если поиск выполнялся, проверенную альтернативу. Она объясняет компромиссы; числовые карточки берут значения исключительно из расчётного ядра. Текст модели всё равно может содержать неточность — сравнивайте его с таблицей расчёта.

Ключ хранится только на сервере: локально в игнорируемом `.env.local` (`OPENAI_API_KEY`), в публикации — в Cloudflare Secret. Клиент и `/api/health` его не получают. Образец имён переменных — `.env.example`, ключ в нём пустой. Модель по умолчанию `gpt-6-astra`, её можно задать через `OPENAI_MODEL`. Время ожидания ответа ограничено 25 секундами. В Node.js успешные ответы кешируются на 10 минут, максимум 100 наборов на процесс; в Worker кеш ответов не используется. Запросы используют `store:false`.

Без ключа, при отказе, таймауте или ошибке провайдера включается явно помеченное расчётное пояснение. При локальном запуске Node.js рекомендация проверяет допустимые замены одного решения, включая смену района. Это локальное улучшение, **не обещание глобального оптимума**. В публичном Cloudflare Worker перебор замен отключён для соблюдения CPU-лимита; пояснение явно сообщает «Поиск замены не выполнялся». Автоматические тесты транспорта используют подставные ответы; фактический ответ живой модели с публичного адреса сохранён отдельно в `docs/evidence/public-ai-smoke.json`.

В публичном демо серверный ключ настроен; посетителям свой ключ или подписка не нужны. Живой ответ `mode:ai`, `available:true`, модель `gpt-6-astra` проверен 23 сентября. Общая демо-квота — 100 обращений к модели за всё время, не более 10 в минуту и двух одновременно; счётчик сохраняется между перезапусками. После лимита остаются карта, расчёты и расчётное объяснение. Ключ демо истекает 30 сентября 2026; для дальнейшего AI потребуется обновление серверного секрета. Публикация сайта и push не заменяют финальную отправку на платформу.

## Архитектура и источники

### Обращения жителей

Модуль из восьми идей Trello реализован отдельно в `src/complaints/` и страницах `citizens.html` / `mayor.html`. Категория, краткое описание, приоритет с обоснованием и возможный повтор определяются **локальными правилами**, допускают ручное исправление и явно обозначены в интерфейсе. Это не живой ИИ-анализ: подключение и проверка LLM для жалоб остаются отдельным незавершённым пунктом. Существующий AI-анализ симулятора на обращения не распространяется.

Список поддерживает поиск, категорию, район, приоритет и статус. Схема координат отображает только переданные точки с широтой/долготой; границы районов не выдумываются. Выбранную точку можно открыть на географической карте OpenStreetMap в отдельной вкладке; адрес можно передать в поиск только по нажатию. Без действия сотрудника внешних запросов к карте нет. Адреса без координат показаны отдельно; автоматического геокодирования в этой версии нет. Ссылки на карту соответствуют [документации OpenStreetMap](https://wiki.openstreetmap.org/wiki/Export#Links_to_the_Map).

Хранилище: `var/complaints.json`, вне статики и Git. Записи атомарные, операции одного процесса сериализованы; для другого пути задайте `COMPLAINTS_FILE` вне `public`. Поддерживается один сервер, работающий с файлом: не запускайте несколько независимых серверов с общим JSON. Повтор Telegram `update_id` не создаёт новое обращение. Публичная проверка требует номер и случайный личный код, не отдаёт текст жалобы, адрес, координаты, фото и Telegram ID. Публичное решение вводит сотрудник; в него нельзя включать личные сведения. Исходное фото хранится как серверный Telegram file ID и загружается для авторизованной панели через ограниченный прокси.

По умолчанию панель работает как локальное демо на loopback. При удалённом использовании задайте `ADMIN_TOKEN` в игнорируемом `.env.local`; панель попросит этот ключ и хранит его только в памяти страницы. Удалённый доступ без настроенного ключа закрыт. Перед эксплуатацией с настоящими обращениями потребуются индивидуальные учётные записи сотрудников, политика хранения и резервные копии; текущая версия предназначена для проверяемого MVP.

Для Telegram задаются `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без `@`), `TELEGRAM_WEBHOOK_SECRET` и, при наличии доступного жителям сайта, `PUBLIC_BASE_URL`. Токены не вставляют в репозиторий, Trello или клиентский код. Без них веб-форма работает, а кнопка бота сообщает, что подключение ещё не настроено.

Для локального запуска Telegram после настройки бота:

1. Запустите сервер через `npm start`.
2. В другом терминале с тем же `.env.local` выполните `npm run bot`. `BOT_SERVER_URL` по умолчанию `http://127.0.0.1:3000`; измените его при другом порте.
3. В приватном чате: `/start` → `/agree` → текст или фото с подписью → при необходимости `/address улица, дом` и геолокация → `/send`.
4. Сохраните номер и код. `/status НОМЕР` в том же чате показывает статус; на сайте нужны номер и код. `/cancel` удаляет текущий черновик.
5. Измените статус в панели. Ответ бота приходит после сохранения решения. При ошибке доставки решение остаётся сохранённым, а панель сообщает об ошибке; житель может запросить статус снова.

Polling передаёт обновления в единственный HTTP-сервер и не пишет JSON отдельно. Не запускайте polling одновременно с зарегистрированным Telegram webhook. Альтернатива — HTTPS webhook `/api/telegram/webhook` с секретом заголовка `X-Telegram-Bot-Api-Secret-Token`; его регистрация и публикация сервера при разработке не выполнялись. Черновики чата живут в памяти 30 минут; после перезапуска незавершённый черновик нужно отправить заново. Завершённые обращения и квитанции сохраняются.

Автоматические проверки Telegram используют синтетические сообщения и подставной транспорт, ничего не отправляют в настоящий Telegram. Сквозная проверка и статус каждой идеи — в `docs/citizen-verification.md`.

Районные метки — условные точки, не официальные границы. Наличие 3D-зданий зависит от покрытия OSM. Для постоянной работы акимата нужны проверенные данные, калибровка эффектов и эксплуатационный план.
